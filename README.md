# AI 历史穿越模拟器

这是一个长期开发的个人项目：玩家进入历史背景，自由描述行动或选择 AI 提供的选项，让故事沿着自己的选择发展；程序保存时间、人物、物品、关系和事件，让长篇游玩及不同世界线仍能保持一致。

项目的核心是“可持续游玩的历史世界”。AI 负责叙事和角色表现，程序负责已经发生的世界事实，研究资料提供历史依据。现实史实、游戏中已经发生的事情、人物各自知道的事情需要分开保存。

## 使用目标与平台顺序

- **Android 是产品优先平台**，重点照顾手机上的中文阅读、行动输入、存档和长期游玩体验。
- **Windows 是主要开发环境，也需要能够实际游玩**，用于调试核心机制和验证桌面体验。
- **网页版安排在后续阶段**，在共享核心与存档协议稳定后实现。
- 项目首先服务于个人使用，成熟后再考虑发布到 GitHub。公开前确定代码许可证、第三方数据授权和发布方式。

各平台的具体交付顺序、共同核心及阶段验收以[第二版计划](docs/PLAN_V2.md)为准。

## 当前实际情况

截至2026-10-16，M03～M05工程基线已建立，M06已接入七页导航、窗口草稿、正式`.timejump`世界包、严格原子导入、持久调用台账、脱敏输出诊断和用户单价费用估算。双端优化构建和私人APK已产出；真实模型完成30个主线行动、摘要/分支/快进和默认预算时间补测，保留失败及质量限制。Windows实际选择器及优化版重启已验证；新手机包、跨端迁移、保数据升级和用户体验仍待验收，当前不是正式v0.1发行版。详见[M06验证](docs/validation/M06.md)、[构建交付](docs/RELEASE.md)、[真实评测记录](docs/validation/M06_REAL_MODEL.md)及[费用验证](docs/validation/M06_COSTS.md)。

文档工作、代码构建和设备验收分别记录，真实完成情况只维护在[任务台账](docs/TASKS.md)；当前工作现场与下一步见[现场状态](docs/STATE.md)。用户已完成部分无线真机验收，当前要求先开发、稍后复测；D024允许M02核心/Windows先行，Android设备证据依实际结果登记。

开发命令与精确工具版本见[开发说明](docs/DEVELOPMENT.md)。可用 `pnpm dev` 预览界面；普通浏览器会提示原生未连接，不能在浏览器中验证 Rust 功能或游玩。

实际操作见[开发版使用说明](docs/USER_GUIDE.md)。正式存档保留本世界全部世界线和必要注释/冻结资料，排除Key及本机配置；同ID导入拒绝覆盖。新设备需要重新配置接口。游戏中的“存档”页面与“技术验证”的文本探针包分别使用。

Windows当前私人优化入口为`target/release/lishi-app.exe`，已内置界面，可直接启动，无需Vite；旧debug构建不代表本次最新版本。打开后创建世界，默认固定规则演示；在“AI接口设置”保存服务后选择“自定义AI接口”才联网。默认要求HTTPS，用户明确选择时可启用HTTP，并会显示Key明文传输说明。失败不会改正式事实，也不会自动重试。默认容量不能容纳所有长局，按实际服务容量调整，详见使用说明。

游戏世界分别保存在应用私有目录内的SQLite，生产Key另由平台加密保存；测试笔记/技术恢复库保持独立。APK路径、使用入口和限制见开发说明；[正式回合契约](docs/contracts/TURN_V1.md)说明当前存档与输出边界。

## 后续工作方式

按台账中具备依赖条件的任务逐项推进，每项交付都留下实际成果和验收证据。优先验证完整回合、持久状态、故障恢复、长期记忆和世界线隔离，再扩展平台与功能。具体范围及优先级以当前计划和任务台账为准。

开发过程中的 Markdown 文档用于让人和 AI 恢复项目上下文；游戏运行时的回合、人物和世界状态采用计划中的 SQLite 存档系统。开发交接文档不充当游戏数据库。

涉及 AI 服务的后续实现需要妥善处理用户自带的 API Key。密钥不得写进项目文档、游戏导出、日志或 Git 提交。M00 未创建远程仓库或上传项目资料；后续公开或上传按用户明确指示执行，并完成许可检查。
