# AI 历史穿越模拟器

这是一个长期开发的个人项目：玩家进入历史背景，自由描述行动或选择 AI 提供的选项，让故事沿着自己的选择发展；程序保存时间、人物、物品、关系和事件，让长篇游玩及不同世界线仍能保持一致。

项目的核心是“可持续游玩的历史世界”。AI 负责叙事和角色表现，程序负责已经发生的世界事实，研究资料提供历史依据。现实史实、游戏中已经发生的事情、人物各自知道的事情需要分开保存。

## 使用目标与平台顺序

- **Android 是产品优先平台**，重点照顾手机上的中文阅读、行动输入、存档和长期游玩体验。
- **Windows 是主要开发环境，也需要能够实际游玩**，用于调试核心机制和验证桌面体验。
- **网页版安排在后续阶段**，在共享核心与存档协议稳定后实现。
- 项目首先服务于个人使用，成熟后再考虑发布到 GitHub。公开前确定代码许可证、第三方数据授权和发布方式。

各平台的具体交付顺序、共同核心及阶段验收以[第二版计划](docs/PLAN_V2.md)为准。

文档工作、代码构建和设备验收分别记录，真实完成情况只维护在[任务台账](docs/TASKS.md)；当前工作现场与下一步见[现场状态](docs/STATE.md)。用户暂时不做真机测试，仍保留完整 M01 门槛。

开发命令与精确工具版本见[开发说明](docs/DEVELOPMENT.md)。可用 `pnpm dev` 预览技术探针界面；普通浏览器会提示原生未连接，不能在浏览器中验证 Rust 功能或游玩。

Windows 原生入口为 `target/debug/lishi-app.exe`；APK 路径与验证边界在开发说明和[M01验证记录](docs/validation/M01.md)中。测试笔记保存在应用私有目录，不是正式游戏存档。

## 后续工作方式

按台账中具备依赖条件的任务逐项推进，每项交付都留下实际成果和验收证据。优先验证完整回合、持久状态、故障恢复、长期记忆和世界线隔离，再扩展平台与功能。具体范围及优先级以当前计划和任务台账为准。

开发过程中的 Markdown 文档用于让人和 AI 恢复项目上下文；游戏运行时的回合、人物和世界状态采用计划中的 SQLite 存档系统。开发交接文档不充当游戏数据库。

涉及 AI 服务的后续实现需要妥善处理用户自带的 API Key。密钥不得写进项目文档、游戏导出、日志或 Git 提交。M00 未创建远程仓库或上传项目资料；后续公开或上传按用户明确指示执行，并完成许可检查。
