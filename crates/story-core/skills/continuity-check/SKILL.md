# 情节连续性检查

## 范围

默认只检查玩家指定段落、当前场景及必要邻文；玩家要求更大范围时先界定实际检查范围。不为简单改稿先扫描整部故事，也不承诺发现全部文学矛盾。

## 检查流程

1. 读目标正文、相关状态和必要前后文。普通查询使用本次提供的 read_world、read_characters 和 read_history；返回定位后读实际内容，摘要只辅助寻找旧事。
2. 逐项检查本次涉及的关键变化：谁在场、物件由谁持有、人物位于何处、经过多久、谁知道什么，以及行动能否导致写出的结果。无关人物与设定不展开。
3. 区分真实矛盾、正文省略、可靠叙述与角色误解。没有写出不自动等于没有发生；原著可能发生的节点也不等于本局必须补齐。人物知情问题按 character-knowledge 核对，原著细节按 canon-reference 核对。
4. 将疑点与本局实际正文、玩家明确设定或原文分别对应；不把摘要、模型记忆或另一条路线当作当前证据。资料不足时指出缺口，不编出一个确定答案。
5. 涉及时间、钱物或状态的记录，用 preview_turn_record 预演影响。预演只检查程序规则，不证明叙事解释或原著事实一定正确。

## 输出与局部改稿

先说明检查范围及最影响理解的问题，再逐项给出处、影响和建议。未发现矛盾时只说在已查范围内未发现，不声称整局无误。报告、内部标识和工具日志不写进小说正文。

玩家选择局部改写时，只改选中范围；正文以外的记录仅返回受影响的最小补丁，保留无关字段。原著细节更正、遗漏补全和玩家分支分别说明。跨回合问题单列，由玩家决定是否交给Agent，不扩大一次局部采用的范围。

人物台词与旁白事实不符，不直接证明他在撒谎、欺骗或有某种动机；也可能是误会、转述或省略。报告只能指出说法与已知事实不一致，未给意图依据时不得确定人物心理。

## 按需支持资料

需要细化核对或答复结构时，用 read_skill_resource 读取 references/method.md；examples/check.json 是独立原创示例，只用于理解方法，不能当本局事实、玩家授权或原著依据。使用读取技能时返回的固定版本与资源定位；普通调用携带 version，Agent使用本任务已读取版本，不预先加载全部附件。

## Agent执行

用 search_resources / list_resources 找到相关 node、people、cards、goals 和 chapter，再按 ref 用 read_resource 阅读。确实需要重算历史时，用 read_timeline 批量读相关时间记录，不为日期显示校准遍历全局。

先形成具体疑点及依据；玩家要求实际修订时，用 stage_edit 暂存相互关联的正文、记录、状态和摘要，用 validate_changes 预演再自行检查叙事逻辑。遵循 world-upkeep / canon-reference 的采用与出处规则，关联资源不能拆成不一致的半份。最终区分已正式采用、等待预览、仅报告及尚待核实，不用“工具完成”代替目标结果。
