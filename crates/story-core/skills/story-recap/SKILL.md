# 故事回顾

## 适用情景

玩家回来继续阅读、询问目前处境、回顾某个人物或指定阶段时使用。先确认本次回顾范围；范围未指定时，以当前场景及近期变化为主，不扫描整局每一回合。

## 读取与核对

1. 读取本次提供的当前世界、人物、目标和章节资料。普通查询用 read_world、read_characters、read_history；只调用本次实际提供的工具。
2. 从摘要定位关键事件，再按需回读实际正文。核对人物当前状态、玩家已经作出的选择，以及有明确依据的承诺、欠款和未解问题。摘要不替代冲突处的原文。
3. 严格区分已经发生、玩家打算、角色猜测和未来可能性。原著只提供参考，不把原著后续写成本局回顾；需要原著核对时另读 canon-reference。
4. 遇到缺页、互相冲突或只有传闻的内容，说明具体不足；不为了让回顾完整而补造事件。不把其他路线的事情并进当前路线。

## 输出与完成依据

先简短说明“现在在哪里、与谁在一起、正在面对什么”，再列必要的近期变化及仍待玩家决定的事。玩家指定人物或阶段时围绕该范围回答，不重复整本梗概。

关键结论附工具实际返回的回合、章节或出处定位；没有定位不编造编号。只声称回顾了本次实际读取的范围。工具返回了目录、定位或分页游标，不代表读过对应全文。

查询只回答，不写入正式剧情、不推进时间、不替玩家作决定。不能以“已读取技能”或“计划完成”代替实际回顾。资料不足可部分完成，并明确尚未确认的范围。

## 按需支持资料

需要细化核对或答复结构时，用 read_skill_resource 读取 references/method.md；examples/check.json 是独立原创示例，只用于理解方法，不能当本局事实、玩家授权或原著依据。使用读取技能时返回的固定版本与资源定位；普通调用携带 version，Agent使用本任务已读取版本，不预先加载全部附件。

## Agent执行

独立Agent先用 read_world 了解配置，再用 list_resources / search_resources 定位必要的 node、chapter、people、goals 和 facts；按返回 ref 用 read_resource 读取。分阶段需要历史时间记录时再用 read_timeline，不逐字段遍历全部历史。

保持只读即可完成回顾。玩家另行要求整理正式记忆时才读取 world-upkeep，暂存、预演并按当前采用策略保存；任务说明和回顾本身不能作为一条新剧情提交。完成答复保留已查范围、真实出处与未解决事项。
