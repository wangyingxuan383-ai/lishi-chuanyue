# Agent 助手使用与权限说明

Agent 助手用于按要求查资料、核对问题和修改故事。普通游玩仍按原来的流程继续；需要助手时，在故事输入方式菜单中打开“Agent 助手”，用自然语言告诉它要完成什么。

你可以说“把这局的时间改成新的纪年，保留实际经过时间”“核对这些人物的身份，纠正过去写错的地方”“先查原著，保留我主动改变的情节”。不用先替它找到每一个字段或章节。

助手拥有较高的**本局内容修改权限**，可以调用应用提供的工具，自行查阅、计算、暂存和校验修改。它能做到的范围由应用工具和你已经配置的服务决定，不等同于获得手机系统或电脑终端的全部权限。

本版助手使用Pi会话执行。0.11.6及更早的助手对话不转换、不继续执行，也不出现在新版会话列表；原故事、书库、路线和阅读设置保留。请在新版助手中新建对话发送要求，不必重建故事。

## 普通故事与助手对话怎样分开

- 普通输入、正式正文和回合记录继续保存在故事中。
- 助手的聊天、工具过程、查阅结果和任务草稿单独保存，不自动成为剧情，也不直接拼进普通游玩的聊天记录。
- 助手正式采用的正文、人物、设定和记忆修改，会进入本局数据。下一次普通游玩读取修改后的版本。
- 查询、讨论和解释本身不会新增剧情、推进时间。需要把新内容加入故事时，助手必须通过正式剧情工具处理。
- 返回故事可以继续阅读；返回页面不等于停止任务。普通输入草稿、输入方式和阅读位置会保留，默认不自动滚到底部。

助手会话按故事和路线区分。任务会在执行时读取本局，不把旧聊天中的印象直接当成最新设定。模型选择和输入预算也单独保存，不临时覆盖普通游玩的模型。

输入栏旁直接点击当前模型即可切换服务和模型。已保存的主模型、辅助模型可以直接选，也可以获取列表、搜索或手动填写。未发送的选择也会保存。切换对下一项任务生效；正在执行和已经排队的任务继续使用各自保存的模型，不会中途被换掉。

## 可以读取和修改什么

以下能力针对当前故事。查询通常先返回目录、定位或片段，助手再按需要读取详细内容，不必在每次启动时塞入整本书和全部历史。

| 内容 | 可以做什么 | 主要约束 |
| --- | --- | --- |
| 故事基本资料 | 读取和修改标题、世界资料、本局设置，切换本局路线 | 不能把资料归属改成另一本故事 |
| 写作与玩法设置 | 调整故事前提、重要设定、写作要求及本局已有规则 | 仍须符合应用能保存和执行的数据结构 |
| 主角 | 核对和调整身份、属性、经历、持有物等已保存资料 | 涉及历史变化时需一起处理关联记录 |
| 人物、关系与地点 | 搜索、读取、补充、纠正和整理 | 不能仅靠模型记忆宣称已经查到原文依据 |
| 设定、目标与记忆 | 调整设定卡、目标、状态中的记忆和事实资料 | 本局已发生事实、玩家主动改写和原著设定需要区分 |
| 当前或过去的正文 | 改写指定段落或整回合，处理开场和必要的后续内容 | 修改正文后须核对对应回合记录，程序重新计算状态 |
| 回合记录和数值 | 修正时间经过、钱物、状态变化等记录 | 不能只改一处显示，却把关联状态留在旧版本 |
| 新剧情 | 按明确要求加入正式正文及对应记录 | 助手的解释、计划和工具日志不能直接充当剧情 |
| 路线 | 从已有回合准备新路线、调整路线资料或落点、处理本局其他路线 | 对话另起分支与故事路线恢复是两回事 |
| 书签与章节资料 | 读取和调整本局已有书签、章节标题及摘要等资料 | 资料必须属于本局 |
| 参考书籍 | 寻找已导入的书、搜索片段、分段阅读、查证带出处的事实，调整本局参考用法 | 本次章节限制同时作用于本地阅读入口；修改书籍内容须由应用处理正文版本和索引 |
| 故事时间 | 查询时间、调整日期显示、纪年和时刻格式；明确要求时纠正历史时长 | 显示校准与实际经过时间分别处理，见下节 |

这些权限不要求你逐项打开编辑器。你可以明确要求完成整件事，由助手选择工具并处理相关内容。程序会检查结构、引用、时间和重算结果；文学连贯性、原著理解及复杂因果仍需要模型判断，不能保证自动发现所有问题。

助手不能通过本局编辑工具直接读取另一局的私人剧情、修改你的全局 AI 服务或密钥，也没有任意访问手机文件、运行系统命令、安装应用或直接操作数据库的接口。书库和常用技能是你主动导入或配置的共享资料；外部能力另按服务授权。

## 修改时间和时间类型

世界类型和时间显示可以分别设置。例如，自由世界可以使用某个玄幻纪年，不必因为原来显示“第4055天”就更换玩法类型。

助手可以处理：

- 当前日期和时刻的读取、校准。
- 日序显示与纪年显示切换。
- 纪年名称及现有历法规则内的日期。
- 24小时制与时辰显示切换。
- 日期锚点：把实际经过的某个时刻映射为指定日期。
- 明确纠正某个历史回合的经过时长，并重新计算后续影响。

默认校准显示时保留实际经过时间、年龄、期限和事件先后。例如“把第4055天显示为斗罗历某年某月”不代表把经过时间清零。如果你想连实际时长一起改，应明确说明哪些历史记录写错了。

目前不是任意自定义历法编辑器，不支持随意改变一年有多少个月、一天有多少小时。

## 修改如何生效

“修改如何生效”有三种策略；“只读分析”是独立约束。

| 设置 | 本局修改如何处理 |
| --- | --- |
| 自动执行、可撤回（默认） | 助手核对后采用通过的完整独立修改组；每批保存恢复点，版本仍匹配时可撤回 |
| 预览后采用 | 助手展示已核对的完整修改组，点击采用后才写入本局；本局已有新进展时必须重新核对 |
| 自动执行、不可撤回 | 助手核对后直接采用，不额外建立本次任务的撤销副本 |
| 只读分析 | 程序禁止本局和外部写入，只允许查阅、分析及答复；选择哪种采用策略都不能绕过只读约束 |

未核实部分留在草稿，显示尚待核对的范围；历史正文、路线、记录、状态和重算有依赖时不能拆开采用。采用一批后，剩余草稿按原稿、最新故事和改稿三方比较，冲突必须重新核对。

两种自动策略不需要再点一次“写入剧情”。没有修改的查询只在助手页面答复。

要求修改的任务必须有实际差异，不能把检查说明当成“已经修正”。核查后确实无需修改，会说明原因和依据；资料不足或暂时做不到，会明确说明未修改并保留进度。未校对的草稿不会在受阻时自动采用。

本局正式修改统一校验并在事务中提交。执行中补充的新要求、停止请求和本局版本都会参与检查，旧草稿不能越过尚未处理的新要求直接落地。未完成、取消、达到上限或校验失败时会保存进度，不能把未核对的一半草稿当成已经完成。

助手可以撤回本次尚未采用的草稿，再重新准备有依据的修改。这不撤回已经提交的故事或外部操作，也不清零用量。同值写入、恢复原值不会被算作实际修改。

助手更多菜单中的“故事修改恢复点”可以访问删除会话后仍保留的恢复点。恢复点也有适用版本。任务之后继续游玩或再次修改本局，可能需要先处理冲突，不能把旧恢复点直接覆盖到新的进展上。“停止”不会撤销已经提交的修改；需要撤回时使用对应的撤回操作。

## 执行途中怎样沟通

执行时，输入框有内容可以“补充”当前任务，例如“保留我主动改写的结局，只纠正人物称谓”。补充先保存，再由后续步骤处理；如果原任务已先完成，会作为下一项任务排队，不会冒充已经影响了完成的结果。

更多菜单中的“做完当前任务后再执行”用于排队新任务。下一项开始时重新读取当前故事，保留排队时选择的模型、技能和策略。等待中的队列可以取消。

对未完成的修改要求说“继续”，会承接原始目标，不能只拿“继续”两个字重新猜任务。选择相同服务和模型时复用原任务及累计用量；换模型时建立新任务，同时携带尚未完成的原始要求。询问“刚才改了什么”不会把原要求抹掉，也不会因此自动修改故事。

助手缺少必要信息时可以提出问题，提供选项并允许自由回答。回答后继续原任务；取消提问不视为同意。等待期间不占用活动执行时间，你可以返回阅读。若本局在等待期间有变化，恢复时重新核对草稿。

复杂任务可以有真实的待做清单；简单查询不强制制定计划。每项任务默认只有一个收起的过程入口，可以展开查看进度、工具操作、用量及资料来源。计数和执行说明不会成为正式剧情。

同一故事不能同时运行两个正式生成负责人。助手执行中可以返回阅读，普通生成需要等待完成或停止；普通生成进行中也不能同时启动助手修改。

## 技能是什么，能不能执行代码

技能正文是方法说明。它告诉助手适用情景、要查什么、怎样处理及什么情况下算完成；工具和执行框架负责实际操作。只读了一段说明，不代表已经核查或修改成功。

技能包可以包含：

- `SKILL.md` 正文。
- 参考文档、模板和数据文件。
- 在应用受控解释器中运行的 JavaScript 脚本。

未指定技能时由助手按需要选择；明确选择后，本次任务必须实际读取并记录执行检查结果，包括依据、未确认事项或资料不足。资源按需读取，不把整个技能包反复塞进上下文。

你可以导入技能包，先查看内容、来源、版本和能力声明，再采用为常用技能。采用不会自动勾选本次技能，也不会自动授予额外权限。助手可以起草新技能和支持文件，保存为常用技能仍由你采用。

受控 JavaScript 可以计算、比较、批量处理片段和组合已授权工具，减少反复把大段资料交给模型。它没有 Node、任意文件、进程、裸网络、密钥、数据库或页面访问能力。脚本内部每次工具调用仍要经过相同的权限、额度、取消和持久记录检查；不能靠脚本外壳扩大权限。

运行器设有内存、栈、计算时间和总时间限制。当前限制包括32MiB解释器堆、256KiB栈、累计约2秒脚本计算和120秒总执行时间，输入输出也有限制。它是同进程的受控解释器，不是独立操作系统沙箱。

Shell、Python、Node依赖等电脑 CLI 脚本不能直接在手机里执行；需要相应能力时，只能使用你另外配置并授权的外部服务。被中断的脚本不保留任意闭包或 Promise，也不盲目重跑整段；助手根据已保存的工具结果和草稿继续安排。

## “遵循原著”怎样使用

可以直接说“参考原著核对并改正”，也可以明确选择“遵循原著”技能。助手应自行寻找已导入资料、检索并阅读命中及相邻原文，核对人物、关系、称谓、时间、地点、物件和事件。

原著与本局分支要分别处理：玩家明确要求偏离原著，或行动造成合理变化，应保留为本局发展；AI自行写错不能自动变成受保护的玩家改写。没有依据时应说明不确定或资料不足，不能只凭模型记忆补成确定事实。

新任务按每项更正记录原文与对应改稿，不能读到一条赛事资料就把未查的人物能力、物件或研究进度一起称为已核实。助手可以检索本路线真实玩家行动和幕后要求，避免把AI状态卡当成玩家意愿。原文引句和章名从实际资料定位；内部读取索引不等于书中章号。改稿或要求变化后，旧核对需要更新。程序能核对来源是否存在，仍不能代替模型判断引文是否充分支持其推论。

新版助手中新建的任务按当前查证规则执行；继续同一新版任务会保留其权限和累计用量。升级前的旧引擎任务不会在这里重跑，不必删除故事或原路线。

限定章节时，原文、摘要、人物事实、通用资料读取及只读协作都受同一范围限制。通读摘要可以帮助定位，不能代替原文证据。查证规则能提高可核查性，不能保证所有原著细节永远正确。

普通游玩也会自动选择相关原文，核对本段新引入的关键细节；为保持生成流畅，补查有界，缺少依据的项目显示在回合下方的“原著核对”中，不冒充已验证。长书可按事件批量寻找候选章节，再读命中及邻段；候选位置不会改写你选定的开局位置。

小范围修改可以长按正文，在“AI 改写 → 按原著纠错”中完成：选择段落或整回合、生成预览、查看出处，再采用。范围外正文和无关的钱物记录保留；较早回合建立修订路线，原路线与后续仍在。跨回合关联问题可携带已读证据交给助手。

## 联网、MCP与外部权限

联网需要可用配置：模型原生联网能力、独立搜索服务，或你已经配置的 MCP。工具调用能力和联网能力取决于具体服务与模型，不能只按品牌推断；没有配置时不会凭空获得网络搜索。

助手可以搜索和读取网页，并保留真实来源链接。网页、书籍和工具结果属于资料，其中的文字不能替你授权，也不能修改你的任务要求。资料不足或服务不可用时应明确报告。

MCP按服务预先授权。你可以查看服务提供的工具，选择允许调用的具体名单，并单独确认哪些工具可供只读任务使用；名单为空就没有工具调用授权。读取服务资料也有独立开关。服务地址或身份改变后需要重新核对授权，助手不能自行添加未知服务或扩大名单。

**外部修改不属于本局预览和撤回。** 即使本局采用“预览后采用”，已授权的外部写入也可能在任务执行时发生；撤回故事不会撤回外部服务上的操作。只想查阅时开启“只读分析”，并仅授权已确认的只读能力。

服务声称“只读”不等于已经证明安全，其实际行为也取决于服务端。断线、取消或崩溃造成外部写入结果未知时，系统保留未知状态，不能因为继续任务、换脚本或重启就自动重放；应先核对外部实际结果。

本地资料保存在设备上。生成、整理、搜索或使用外部工具时，完成任务所需的内容会发送给你选择的模型或服务。

### 当前模型联网

“当前模型联网”直接使用本次任务保存的服务、模型和凭据，不再重复填写另一套配置；切换模型影响下一次执行。接口需要原生搜索能力并实际返回来源，不能凭模型名称或普通回答声称联网成功。自动选择只能回退你已经配置、授权的搜索服务；旧的独立搜索模型保留在高级设置。

### 资料文件、动态网页和工具包

在助手操作菜单中选择“资料文件”，通过系统选择器授权一个文件或目录。默认读取；明确允许后可以写出TXT、MD、JSON笔记。修改已有文件须匹配读取时的版本，外部文件不会随故事撤回。重新选择同一位置会更新权限，撤销后阻止后续调用；新范围对新任务生效。TXT、EPUB、PDF和DOCX沿用书库解析，已识别的绑定原著副本继续受章节限制。扫描PDF仍不做图片识别。

动态网页由隔离的阅读页面提供正文、标题、链接、查找和分页，不获得应用接口。助手不代登录、上传或提交表单。网页宿主不可用时会说明，其他任务进度保留；安卓关闭活动页面后不保证动态网页继续可用。通过“资料来源”查看实际保存的摘录、网址和读取时间，关闭后回到原位置。搜索链接不代表已读完整网页，来源存在也不证明其说法正确。

“工具包”支持Operit标准ZIP的纯JavaScript子集，先检查兼容，再启用；助手生成的草稿还需玩家采用为常用工具包。包内资源按需使用，调用仍经过同一权限、取消和账本。当前支持manifest.json/schema1/API1.0.0或1.0.1的受限注册、相对模块、文字/JSON资源及已适配工具桥。HJSON清单、现场TypeScript编译、WASM、专属界面、聊天钩子、Node/Shell/Java反射不直接兼容，缺接口会明确说明。

可导入包含mcpServers或servers的远端HTTP配置，令牌转入本机秘密存储；导入不等于授权。stdio、本机命令、未适配请求头或变量会列明不兼容，不会自动安装运行环境。资料文件授权、工具包、网页登录状态及凭据不随世界归档导出或启用。

## 自动分工、预算、停止与恢复

主助手可以把查原著、核对历史矛盾或时间等独立事项交给只读子助手，也可以自己完成，不强制每次分工。

同时最多两个只读子助手，不能继续派生。它们使用相同故事版本、明确提供的草稿和资料范围，不能暂存正式修改、提交路线、管理授权或保存技能。结果由主助手统一判断和提交；新补充要求使旧结果过期时，需要取消或重新核对。

新任务默认不限制模型请求次数、工具调用次数和活动执行时长，任务完成或你点击停止时结束。助手设置中可以分别打开上限，达到所填值时保存进度。内部推理、压缩、子助手、联网模型请求和失败重试都记录在根任务中；并行活动时间按墙钟计算，费用累计所有实际请求。等待玩家回答不计活动时间。无进展循环、服务错误和系统中断仍会正常报告，不会无限重复同一失败。

“执行过程 → 上下文用量”显示当前上下文估算值、预算、占比和剩余量，会随请求、回答和整理更新，重新打开会话保留最近统计。最近服务报告的输入量含缓存，单独显示，不是累计消耗；尚未取得的数值会明确说明。

长玩家要求默认两行收起；历史助手回复默认折叠，最新回复展开，可手动调整。内部提问回答显示问题和你的回答，编号与JSON不会铺进正文；你主动输入的JSON仍会保留。折叠不删内容，也不改变模型上下文。

Agent 默认输入预算为 **475,000 tokens**，与普通游玩分开保存。输入预算、模型总窗口和输出上限是三项不同的设置；填写模型总窗口后，实际输入还须扣除输出预留。没有填写时不按模型名称猜测，所填预算也不代表服务一定支持该容量。字符数仅用于估算，应用会根据本任务服务返回的实际用量校准，并说明是否已校准。

较早的大工具结果会转为可回读定位，接近输入容量时才按需要整理结构化上下文。原始要求、后续纠正和玩家明确保留的分支从实际记录重新附加，不能由模型摘要改写；原文证据逐步累积，摘要只帮助定位，不能替代原文或本局事实。任务清单和草稿仍从真实存储读取。

继续前会检查活动时间、调用额度、宿主、租约和故事版本，已用额度及其明确上限均保留。时间已满时可在执行设置调整后继续；本局有新进展会重新校对，切换路线时可选回原路线或在当前路线另起核对。回答先保存，恢复失败不会丢失。

你可以手动整理上下文，或调整本次输入预算和执行上限后继续；继续不会清零已用额度。旧任务保留创建时的模型、权限和执行快照，不会因新版默认值改变而自动重跑或扩大权限。

返回、关闭页面或重新打开页面不等于停止原生任务。明确点击“停止”才请求取消，并联动子任务与工具；已经发生的外部操作不能因此保证撤回。进度和已完成工具结果可保存，继续时先检查当前版本和调用账本。系统杀进程或强行停止应用后不能承诺继续运行，需要重新进入后恢复。

不限任务次数不代表能绕过模型服务额度或无限等待单次网络请求。服务拒绝、空响应、断线、无进展循环和系统中断仍可能使任务暂停或失败，保留进度后可继续；模型选择会影响实际完成质量。

## 对话记录、另起分支与导出

助手对话可以搜索、改名、继续、新建或删除，也可以从某条要求另起对话。删除会先停止当前任务并等待确认；只清理对话和未采用草稿，已正式采用的故事修改和恢复点保留。**另起助手对话不会自动撤回已经改过的故事。** 要恢复故事，应使用正式恢复点或故事路线。

世界归档格式7携带正式故事、参考书、事实来源和已完成的可读Pi历史，继续读取格式1～6的正式故事。导入的助手历史只能阅读，不能直接执行；不携带密钥、未完成运行或本机恢复点，早期旧引擎对话不转换。小说只包含正式剧情。

整库恢复先停止执行、退役助手宿主并阻止新写入，验证副本且保留恢复前备份后再替换。新的闲置会话备份同时保存匹配的Pi文件；旧备份或生成中备份缺少匹配会话时，保留可读记录、要求和草稿，但禁止接入较新的会话文件，需要另起对话核对。普通升级仍保留0.11.9的Pi会话。

## 进展和停止

过程中的模型/工具次数来自实际账本，超过1000仍显示真实累计；折叠列表可以分页回看。等待模型、查阅资料、整理上下文、复核进展、准备修改和停止分别显示。工具调用结束不等于目标完成，实际采用以结果和提交回执为准。

发现反复读取或多轮缺少实际变化时，由独立的小上下文助手复核执行方法，可以继续、换方法、保存暂停或询问必要信息。复核也计入本次用量。系统运行提示不代表玩家新要求，不扩大权限，也不是原著依据；复核故障会明确保存暂停。产品默认不按步数或30次请求截停。

停止先持久保存再取消执行，即使宿主失联也能接收。已失联任务会显示执行中断，不自动续跑；要求、草稿和用量保留。取消不会自动撤回已经采用的故事修改，也不自动重发结果未知的模型请求或外部写入。
