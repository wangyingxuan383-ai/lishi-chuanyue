## 故障与修复

1. 初次 VS 命令未正确引用有空格的安装路径，实际注册到 `C:\Program`。通过官方卸载移除仅本次 BuildTools 实例，退出0；再以无空格路径 `C:\DevTools\LishiBuildTools` 安装指定 C++/SDK 组件，退出0、isComplete=true、不需重启。未直接移动或递归删除系统安装目录。
2. 显式 Rust toolchain 安装与 Android 初始化隐式安装同时执行，发生下载重命名/回滚冲突，组件清单一度与可执行文件不一致。已完整卸载仅项目指定的1.99.0工具链并串行重装，rustc/cargo/fmt/clippy 均重新核实。以后先完成 toolchain 安装再启动 Tauri 命令。
3. 首个 APK 构建尝试发生在 MSVC 重装期间，返回缺少 `link.exe`，未产生成功 APK。工具安装完成后重新构建，后续结果在下面登记。
4. Tauri Android 模板默认 API37，SDK 管理器实际找不到 `platforms;android-37`，且该警告返回码仍为0。没有因此宣布安装成功；固定现有 API36，并采用官方已发布 AGP9.3.3。buildSrc 与 root 的 AGP 保持一致。
5. 盘点时执行新版 `android.exe --version` 意外触发其自引导下载；并非完全只读。没有用该命令初始化或修改本项目，后续环境设置使用明确的既有 SDK 工具。
6. ARM64 Rust 编译成功后，Tauri 创建 JNI 库符号链接失败。已启用 Windows 开发模式并实际验证普通权限链接成功，重新构建继续打包。
7. Java wrapper 初次下载官方 Gradle ZIP 直连超时。.NET 使用本机既有代理可下载，官方 ZIP 的 SHA256 为 `9c0f7faeeb306cb14e4279a3e084ca6b596894089a0638e68a07c945a32c9e14`；校验后复制到官方 wrapper 缓存，由 wrapper 自行校验解包，未伪造 .ok。进程级代理配置用于后续 Maven 请求。
8. Kotlin 增量缓存因 C盘 Rust registry 与 D盘工程跨根路径报错，首个APK通过非增量fallback成功。项目已明确设置 kotlin.incremental=false，后续重建验证。Tauri模板旧DSL的上游弃用警告保留，不伪称完全零警告。
