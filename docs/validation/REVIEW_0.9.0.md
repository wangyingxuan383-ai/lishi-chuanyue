# 0.9.0 发布前审查

- 时间：2026-10-17（Asia/Shanghai）。
- 范围：`v0.8.0..main` 的全部改动（R11、R12，包括合并进来的角色面板和运势开关）。审查由一个子代理只读完成，主代理逐条核对、修复。
- 方法：读代码、用 node 实测关键函数；没有调用真实模型。

## 发现与处理

| 严重度 | 问题 | 处理 |
|---|---|---|
| 高 | 智谱的 Key（`id.secret`，带点）粘进 Key 框会被当成地址，挪进“服务地址”，从首次引导起就连不上 | 已修：没有 `http(s)://` 也没有路径的带点字符串不再算地址；补了测试 |
| 中 | 对话框的 key 每次渲染都随机，toast 消失等任何重新渲染都会清掉正在输入的名字；被新对话框顶掉的旧请求永远等不到结果 | 已修：每个请求有自己的 id；新请求把旧请求按“取消”结束 |
| 中 | 撤销、回到过去后，toast 上的“重做”“撤回”“回原路线”在故事已经往下走之后点，会拿旧光标移动路线 | 已修：执行前检查故事还停在那一步、也没在写，否则提示“这一步不再适用” |
| 中 | 设置里“运势”“用词提醒”的默认值没有用到新开的局 | 已修：开局时连同难度一起带上 |
| 中 | 出错时点“去设置”打开的是第一个服务，不一定是正在用的 | 已修：打开正在用的那个 |
| 中 | 设置页的临时 Key 槽：返回时的删除可能早于还没写完的保存，进程被杀时也会留下，且从不清理 | 已修：删除先等写入结束；写入前记下槽名，下次启动时清掉 |
| 中 | 首页的世界、建议选项、重说、我的开局只响应指针，键盘回车和读屏双击没有反应 | 已修：没有指针按下的点击（键盘、读屏）也算点按 |
| 低 | 恢复备份时，上一回合的后台整理可能写进恢复后的库 | 已修：恢复前等后台工作结束 |
| 低 | 打开链接失败没有提示 | 已修：提示“没能打开浏览器”，并复制链接 |
| 低 | 备份满 20 份后，恢复列表不随手动备份刷新 | 已修：按最新一份的名字刷新 |
| 低 | 首次引导页用系统返回键离开，下次还会弹出 | 已修：等同“稍后再说” |
| 低 | 生成中，⋯ 菜单的“回到首页”绕过了“正在写”的拦截 | 已修 |
| 低 | “世界数”包含回收站里的世界 | 已修：不算回收站 |
| 低 | 确认框打开后焦点不在框里，也没有 `aria-modal` | 已修 |
| 低 | “写好了”通知靠请求结束 8 秒后推断，失败、取消、设置页测试时也会提醒 | **未修**，下一版改为由前端在写完时明确告诉原生层 |
| 低 | Windows 用 `explorer` 打开链接只过滤空白和引号；`http_get_public` 不限域名 | 未修：链接都是写死的或来自 GitHub，风险低；以后收紧成白名单 |
| 低 | 自定义代理地址里的账号密码明文存在设置里，会进备份 | 未修：以后在网络页提示不要把密码写进地址 |
| 低 | `update.ts` 的 `newer` 不区分 `-rc` 后缀；网页开发台 `getPublic` 忽略超时 | 未修：不影响手机和电脑版 |
