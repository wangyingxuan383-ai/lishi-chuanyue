## Windows 原生应用

`target/debug/lishi-app.exe`，WebView2 开启本机调试端口后由 `scripts/ui/native-devcheck.mjs` 驱动（不占用前台）。对象为本地模拟模型服务：

- 平台识别为 windows；Key 经 DPAPI 保存，页面 localStorage/cookie 中不存在 Key。
- 模型列表经 Rust `llm_get` 获取；正文经 Rust Channel 逐字到达（采样 0,0,12,24,42,60,72,96）；`include_usage` 用量 50/120；停止生效。
- 改用未绑定的地址时，请求在发出前被拒绝，界面显示“地址和保存 Key 时的服务不一致”。（首次运行发现前端把这个拒绝误报为“连不上服务”，已修正错误映射后复测通过。）
- 正常关闭窗口再启动：2 条试写记录与 Key 状态保留。
- 测试结束后已删除测试 Key（界面显示“未保存”）。

Windows 原生应用本身没有对真实模型服务发起请求；真实服务经开发台与评测脚本验证（同一套转发语义）。

## Android（小米 24117RK2CC，Android 16，全面屏手势）

- debug APK 构建与包检查通过：applicationId `io.timejump.chuanyue`，v2 签名（与 v2 测试证书相同），ZIP 与 ELF 段 16 KiB 对齐，JNI 类与方法齐全。加入前台服务后 debug 包约 420 MB（含调试符号）。
- 无线 ADB 二维码配对后 `adb install -r` 直接成功（213 MB 约 35 秒），新旧两个应用共存。
- 手机 WebView 调试端口驱动自检脚本（`scripts/ui/native-devcheck.mjs`，`CDP_PORT=9333 EXPECT_PLATFORM=android`），对象为经 `adb reverse` 转发的本地模拟模型：Keystore 保存 Key、页面读不到；模型列表；逐字流式（采样 0,0,18,36,54,72,90,108）；用量；停止；未绑定地址拒绝；试写保存——全部通过。
- 生命周期（`scripts/ui/android-lifecycle.mjs`）：
  - **首次发现问题**：生成中按 Home 切后台 30 秒，回来正文停在 90 字。诊断（`scripts/ui/android-bg-probe.mjs` + `dumpsys netpolicy`）：应用进入后台约 5 秒后系统对其 UID 施加 `blocked=APP_BACKGROUND`，请求被切断，进程本身没有被冻结。
  - **修复**（R01-T007，D116）：生成期间启动 dataSync 前台服务。复测：切后台 30 秒回来正文完整（6→151 字）；生成期间服务运行、网络 `effective=NONE`，结束后服务消失、网络恢复为 `APP_BACKGROUND`。
  - 强制停止后重新打开：试写记录与 Key 状态保留。
  - 返回：按键注入与左缘手势滑动均被接管，第一次提示“再按一次退出”且应用保留，连按两次退出。
- 通知：因尚未申请通知权限（Android 13+），生成期间的通知不显示，服务照常工作；申请时机放到 R02 首次生成前。
- `tauri android dev`（真机热更新）：三次尝试均无法识别无线调试设备、回退为打开 Android Studio，未采用。

## 发现的问题

- 前端曾把 `llm_url_not_bound` 拒绝误报为网络错误 → 已修正（`chat.ts` 按错误码映射；开发台实现也改为在发起前拒绝，与原生一致）。
- PowerShell 中 Tauri 构建找不到 `pnpm` → `scripts/Enter-Dev.ps1` 自动在 `.cache/bin` 建 corepack 垫片。
- pnpm 11 拦截了 esbuild（tsx 依赖）的安装脚本 → 在 `pnpm-workspace.yaml` 中 `allowBuilds: esbuild: true`。
- Codex 沙箱内的 `cargo check --target aarch64-linux-android` 因缺少 NDK 编译器路径与 Cargo 缓存目录写权限失败；主代理用 `pnpm tauri android build` 正常完成。
- 浏览器自动化工具的视口模拟在本机不生效，改用 `playwright-core` 调用本机 Edge。
