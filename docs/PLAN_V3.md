## 0. 本计划怎么用

- **目标顺序**（用户 2026-10-16 明确）：
  1. 学习同类型的项目，做到体验上类似成熟产品；
  2. 根据“历史穿越”的项目特色做出适配；
  3. 让使用者在体验中感觉舒适好用；
  4. 改善 UI 和前端（工程量大，**后置**到 R09）。
- **平台顺序**：专注 Android 手机 App；电脑端（Windows）只需能运行、方便调试，不专门做体验。
- 每个阶段都有**进入条件**和**完成门槛**；从 R02 起，完成门槛必须包含用户在手机上的试玩评价（第 8.4 节），不能只靠“测试通过”。
- 计划里写的是“要做什么、为什么、做到什么程度算好”。具体做到哪了，以台账为准；计划被新要求推翻时，先更新本文件和决策记录，再动代码。
- 标注 **【待验证】** 的内容是合理假设，需要在对应任务里实测后才能当作结论。
- 标注 **（R0x）** 的功能表示在该阶段实现；没有标注的属于 R02 的基础功能。

## 1. 为什么要重构：现状诊断

v2（Codex 阶段，2026-10-11～10-16）交付了约 6.4 万行代码，其中 Rust 核心与测试占绝大多数，前端约 8 千行。工程上做了大量事务、校验、恢复、审计工作，测试数量很多；但用户实际使用时“无法代入、不便操作、很多功能不好用、界面丑”。下面是具体原因，后续设计逐条针对它们。

### 1.1 玩家直接感受到的问题

| 问题 | 证据（v2 实际情况） | v3 对策 |
|---|---|---|
| 回合经常失败 | 真实评测 36 次生成中 6 次被整回合拒绝，原因是模型输出的 JSON 少字段、多字段或引用错误；每次都要玩家手动重试 | 正文与记录分离，记录宽容解析、逐条应用，坏了也不拒绝回合（D104） |
| 等待太久、没有“写作感” | 每回合单次请求 7～23 秒；正文放在 JSON 字段里，流式显示的是“草稿”，体验像等待审核 | 正文纯文本流式逐字出现；首字尽快出现（第 5.7 节） |
| 越玩越贵越慢 | 到第 30 回合，每回合要发送约 2 万 token；默认 8KB 上下文又装不下长局，需要手动调参数 | 分层上下文（故事卡、章节摘要、最近原文），按预算自动取舍（第 5.3 节） |
| 玩起来像记账 | 主角在长安搬货、买胡饼、核对“118 记账单位”；初始资金统一是“100 记账单位”，与时代无关 | 时代货币与物价（时代包）；数值只保留少量核心项，服务于剧情（D113） |
| 开局毫无代入 | 开局是一张表单：世界名称、国家、公元年份、地点、主角姓名；没有身份、处境、穿越方式，也没有开场戏 | 穿越向导 + 身份抽签 + “感官→纪年→原主记忆→危机”式开场（第 4.2 节） |
| 界面说的是工程师的话 | 文案大量出现“核心已确认”“操作 ID”“正式世界节点”“不会自动重发”“可能产生费用”；技术验证页面挂在主导航上 | 全部改为玩家语言，技术信息只在“开发者模式”里（第 4.12 节） |
| 操作不顺手 | 七个标签页平铺；没有成熟产品常见的“重说多版本切换、直接编辑 AI 文字、回到这里、继续” | 采用 AI Dungeon / SillyTavern / 星野验证过的操作集（第 4.4 节） |
| 安卓基本交互缺失 | 没有处理返回键（按返回直接退出）；应用名仍是 “Lishi Probe” | 返回键逐层关闭；新应用名与图标（R01、R09） |
| 设置门槛高 | 要手填完整 Chat Completions 端点、输入字节上限、token 上限、预留输出等五项参数 | 服务商预设 + 自动获取模型列表 + 一键测试；高级参数折叠（第 4.11 节） |
| 失败没有后果、世界不落地 | 评测中行动几乎都顺利完成；NPC 没有自己的目的 | 轻量“运势”裁定 + NPC 动机 + 时间推进中的世界事件（第 5.5、4.6 节） |

### 1.2 工程与过程上的问题

- **验收标准只问“有没有出错”，不问“好不好玩”。** 所以投入集中在原子提交、强杀恢复、调用审计、存档 schema 校验上，这些对一个个人游玩的文字游戏来说过度了。
- **严格协议拖累了一切。** 为了让每个回合“要么全对要么不算”，设计了 18 种操作模板和多层校验；模型很难稳定遵守，于是又不断加提示词、加诊断，形成恶性循环。
- **手机迭代太慢。** 小米手机拒绝 ADB 直接安装（`INSTALL_FAILED_USER_RESTRICTED`），每次改动都要把 APK 放进下载目录手动安装，手机体验几乎没有被反复打磨。
- **文档难读。** v2 文档信息密度极高、句子压缩成缩写，接手时反而难以理解。

### 1.3 v2 中值得保留的东西

v2 并非一无是处，平台层的结论和部分代码可以复用（详见第 11 节）：

- 工具链已经装好并验证：Rust、JDK、Android SDK/NDK、Gradle、签名、16KB 对齐检查脚本。
- 平台能力已经在真机或 Windows 上验证：Android Keystore / Windows DPAPI 密钥保存、Rust 端 HTTP 流式请求与取消、系统证书 TLS、Android 系统文档选择器、输入法与系统栏边距修复、无线 ADB 二维码配对脚本。
- 真实模型的行为教训：时间单位换算出错、动作范围越界（玩家说“先做一段”却写成做完整趟）、正文与状态不一致、条件精度丢失。这些将成为 v3 评测的固定检查项。

## 2. 产品定义

### 2.1 一句话

**一个装在手机里的“AI 穿越小说 + 人生模拟”：你穿越到某个历史时代，成为某个具体的人，用自然语言决定怎么活；AI 把你的选择写成故事，程序替你记住世界的一切。**

### 2.2 体验支柱

每个功能设计、每次评审都用这六条检查：

1. **代入**：第一屏就在故事里。时代的称谓、钱币、纪年、器物、生活细节让人相信“我在那里”。
2. **流畅**：点下去很快就开始出字；单手就能完成大部分操作；没有多余的确认和说明。
3. **掌控**：任何操作都能撤回；不满意可以重说、改写、回到过去另走一条路，永远不怕玩坏。
4. **记得住**：人物、欠债、伤病、承诺、仇怨，过了一百回合依然算数。
5. **有盼头**：有目标、有时间流逝、有世界大事；能看到自己的处境在变化。
6. **有后果**：选择会失败、会付代价；世界有自己的运转，不围着主角转。

### 2.3 目标用户与使用场景

- 首先是用户本人：中文玩家，喜欢穿越小说和历史，愿意自备 AI 服务。
- 使用场景：通勤、睡前的碎片时间（5～30 分钟），单手竖屏；偶尔周末长时间沉浸。
- 由此推出的约束：随时可以中断、下次打开回到原处；字要好读，夜间模式与字号调节从 R02 就要有；单回合默认篇幅为“中”（约 400 字），可调。

### 2.4 版本里程碑

| 版本 | 对应阶段 | 玩家能做什么 |
|---|---|---|
| v0.1 内测 | R02 完成 | 在手机上一键穿越到一个时代，流畅地玩下去：自由行动、选项、继续、重说多版本、撤销、改写，有基础角色面板与阅读设置 |
| v0.2 | R03 完成 | 自定义世界：设定集（时代卡与故事卡）、AI 按故事设定整理时代卡、纪年与货币 |
| v0.3 | R04 完成 | 长局不失忆：故事卡自动维护与人物志、要点、章节摘要、叙事方针 |
| v0.4 | R05、R06 完成 | 时间推进与世界事件、目标、运势；世界线管理 |
| v0.5 私人稳定版 | R07、R08 完成 | 查一查、导出导入、备份、长局性能、私人发行包 |
| v0.8 | R09 完成 | 视觉重设计 |
| v1.0 | R10 完成 | 电脑端适配、公开准备 |

### 2.5 明确不做（至少到 v0.5 之前）

多人联机、云同步与账户、AI 生图与语音、完整经济与战争数值引擎、地图、插件市场、全面历史数据库接入、强制联网考据、模型微调。

### 3.3 v3 的差异化（我们的特色）

通用 AI 故事产品的中心是“角色和聊天”；v3 的中心是**“一个具体的人在一个具体的时代里活下去”**，而这个时代由玩家决定（2026-10-17 起自定义优先，D121）：

- **玩家定义的世界**：故事设定由玩家写；世界资料都放在一个“设定集”里（时代卡、人物、地点、势力、物品、设定），玩家可看可改，AI 写作时照着设定集来。AI 可以按故事设定整理出时代卡（称谓、货币与物价、日常节令、文风、不该出现的东西），架空朝代也一样；内置的唐天宝卡组只是一个可选的示范（第 4.14 节）。
- **穿越题材专属开局**：魂穿（接收原主记忆）/身穿/投胎，原主身份抽签，“原主为什么会死”式危机开场，金手指可选且克制。
- **时间是一级玩法**：时辰、农历日期、节气；“过些日子”快进与月报；人物会长大变老。
- **先知优势有代价**：历史时间线分“固定锚点”（天灾、大势）与“可变事件”（人事），玩家改变历史后记录“历史偏离”。

## 4. 核心体验设计

本节描述玩家看到什么、怎么操作。界面的最终视觉在 R09 才重做；R02～R08 用“干净、好读、不花哨”的基础样式，但**交互和信息结构在这一节就要定好**。

### 4.1 首次打开与前十分钟（2026-10-16 按 D117 修订）

1. **欢迎与连接 AI**：首次打开先连接 AI 服务（可“稍后再说”）；服务商预设、获取模型列表、一键测试，失败用人话说明。
2. **首页**：没有世界时只有一个大按钮“开始穿越”；有世界时下面列出“继续游玩”。
3. **新的故事**（一屏可滚动，所有内容可编辑，见 4.2）。顶部右侧“随便穿”一键开始。
4. **落笔中**：过场只显示到第一个字出现，之后直接看开场流式写出。
5. **开场**：AI 按玩家的故事设定写开场——穿越则从醒来的感官、原主记忆写起，不穿越则从具体场景切入——以一个迫在眉睫的情境收尾，给出选项；或者直接显示玩家亲手写的开场。
6. **前几回合**：状态变化小标签、第一次长按提示、“我”面板的发现提示与原计划相同。

### 4.2 开局设计：作者模式（D117）

开局只有一张“开局设定”，玩家像小说作者一样定下故事，AI 负责往下写，玩家作为主角参与。

| 区域 | 内容 | 说明 |
|---|---|---|
| 灵感 | 内置模板（各阶层、多个朝代）+ 我的开局 | 点一下填入全部字段，随后任意修改；默认显示 6 个，可展开全部 |
| 一句话想法 | 文本 + “AI 帮我补全” | 只补空着的字段，不改玩家已写的内容 |
| 故事设定 | 多行自由文字 | 相当于开局提示词，每一段都会放进上下文 |
| 主角 | 名字、年龄、性别、身份与处境 | 身份隐含性别时显示“由身份决定”（可解除）；中性身份才让选性别 |
| 穿越 | 魂穿 / 身穿 / 投胎 / 不穿越；穿越前是谁 | 不穿越即原住民视角的历史小说 |
| 开场 | AI 来写（可给一句提示）/ 我自己写 | 自己写时 AI 只整理开局状态，正文原样保留 |
| 更多设置 | 故事名、时代设定（AI 按故事设定整理 / 内置卡组 / 不要）、视角（你 / 我 / 他）、文风、篇幅、选项数、内容尺度、要点、给 AI 的额外规则 | 全部可在游戏中修改（“设定集”“故事设定与要点”“本局设置”） |
| 底部 | 存为我的开局 / 开始 | 草稿离开页面后保留 |

- **初始状态**由开场决定：日期（时代说法）、时刻、货币单位（没有时代包时）、主角初始钱数（按身份，皇子与乞丐差别很大）、随身物品、人物、第一个目标。
- **时代设定**（D121）：默认由 AI 按故事设定整理成时代卡放进设定集，玩家可改；选内置卡组（如唐天宝）就直接用整理好的资料；选“不要”时只按故事设定写。
- **游玩中的作者权**：输入模式“写”——玩家写的文字直接成为剧情，AI 视为已发生并接着写；配合改写、回到这里、导演，玩家可以随时把故事掰回自己想要的方向。

### 4.3 主游玩界面（竖屏）

```
┌──────────────────────────────────┐
│ ←  长安·西市   天宝七载冬月十七 酉时  [我] │  顶栏：返回 / 地点 / 时间 / 角色面板
├──────────────────────────────────┤
│ 你：向掌柜打听今日米价                  │  玩家行动（小字、淡色）
│                                      │
│ 掌柜抬了抬眼皮，手里的算筹没停……         │  正文（大字、舒适行距）
│ ……                                   │
│ [钱 −2文] [得 胡饼×1] [过了半个时辰]     │  状态变化标签（点开看细节）
│                    ‹ 2/3 ›   重说     │  仅最新一回合：版本切换与重说
├──────────────────────────────────┤
│ · 去城隍庙看看                         │  选项：纵向列表，点即提交，
│ · 回客栈歇脚                           │        长按把文字填进输入框再改
│ · 打听孙管事的下落                      │
├──────────────────────────────────┤
│ [做▾]  写下你要做的事……         [继续] │  输入栏：模式 / 输入框 / 发送键
└──────────────────────────────────┘
```

- **发送键三态**：输入框为空时显示“继续”；有文字时显示“发送”；生成中显示“停止”。不另设单独的“继续”按钮（360dp 宽屏放不下）。
- **故事流**：一条连续的阅读流，默认只渲染最近 30 回合，向上滑到顶自动“加载更早”；打开世界时回到上次阅读位置；生成中自动跟随到底部，玩家上滑时停止跟随并出现“回到底部”按钮。
- **选项**只在最新回合显示，纵向列表、点击区足够大；滚动中的误触通过“按下后移动超过阈值即取消”避免。
- **手势**：故事流内**不使用横向滑动手势**（避免与系统边缘返回、版本切换冲突）；版本切换只用 ‹ › 按钮；角色面板用顶栏按钮打开。
- 顶栏时间地点始终可见，这是“时间是一级玩法”的体现。
- ⋯ 菜单（顶栏或长按空白处）：撤销、重做、过些日子（R05）、世界线（R06）、查一查（R07）、本局设置。

### 4.4 回合操作集

| 操作 | 入口 | 行为（全部可撤回） | 阶段 |
|---|---|---|---|
| 做 | 输入栏模式“做”（默认） | 主角的行动 | R02 |
| 说 | 模式“说”；输入以引号开头时自动切换（按钮显示已切换，可点回） | 主角说出的话 | R02 |
| 写 | 模式“写” | 玩家以作者身份写一段剧情，直接成为故事的一部分，AI 视为已发生并接着往下写 | R02 |
| 导演 | 模式“导演” | 给 AI 的幕后指令。单独发送时 = 带指示的“继续”；也可以在“做/说”时附加一句导演备注（输入栏上方的小字段） | R02 |
| 继续 | 输入框为空时点发送键 | 主角只做等待、观察这类被动动作，时间小幅推进，由 NPC 和环境推动剧情 | R02 |
| 选项 | 点选项 / 长按填入输入框 | 以选项文字作为“做”的行动 | R02 |
| 停止 | 生成中点发送键 | 停止生成，保留已写部分作为一个“已中断”的回合，可续写或重说 | R02 |
| 重说 | 最新回合“重说” | 同一行动再生成一版，旧版保留，‹ › 切换；长按“重说”可写方向（“写短一点”“让他拒绝我”“换个结果”） | R02 |
| 撤销 / 重做 | ⋯ 菜单 | 回到上一回合 / 前进到刚才的回合；不删除任何内容 | R02 |
| 改我的行动 | 长按玩家行动 | 修改后从该处重新生成（原内容保留为旧路线） | R02 |
| 改写 | 长按正文 | 直接改字，后续生成以改后的文字为准；保留“已改写”标记 | R02 |
| 回到这里 | 长按任意回合 | 把当前位置移到该回合；之后的内容不删除，作为一条可回去的路线保留（第 6.4 节） | R02 |
| 复制 | 长按任意回合 | 复制本段文字 | R02 |
| 记住这件事 | 长按正文 | 把整段带进底部弹层，玩家删改成一句要点后保存（R04 前不显示此项） | R04 |
| 书签 | 长按任意回合 | 收藏到记事页（R06 前不显示此项） | R06 |
| 查看记录 | 点状态标签 | 展开本回合的全部状态变化；开发者模式下另有原始输出 | R02 |

规则补充：
- **重说与运势**：同一父节点下的重说沿用同一次运势（5.5）；只有带“换个结果”方向的重说才重掷，并在标签上标“重掷”，防止刷运气。
- **长按与选字**：正文默认关闭系统选字（`user-select: none`），长按弹出自定义菜单；“复制”提供整段复制。
- **输入法**：中文输入法拼音组字过程中按回车不发送（检查 `isComposing`）；回车默认换行，发送靠按钮。
- **没有任何操作会丢失内容**。真正的删除只在“世界线管理”里，需要二次确认并进入 30 天回收站。

### 4.5 角色与世界面板（“我”按钮）

从右侧滑出的全屏面板（只能用按钮打开，不用边缘手势），顶部分段切换，返回键关闭：

1. **我**：姓名、年龄、身份、外貌一句话；核心数值（钱财、健康、精力、名望，见 D113）用文字档位 + 细条显示（如“健康：带伤”）；持续状态（伤病、增益）；穿越信息（原本是谁、金手指）。
2. **行囊**：物品与数量、存放位置；家产（远期）。
3. **人物**：人物卡片列表（姓名/称呼、身份、关系与态度标签如“友善”“提防”、最近一次相见）；点开看完整卡片，可编辑。人物表就是设定集里的人物卡。R02 为简表，R04 为完整人物志。
4. **目标**：进行中与已完成的目标。R02 为简版，R05 完整版（含“我的心愿”）。
5. **记事**（R04 起）：大事记、章节摘要、书签（R06）、历史偏离记录（R05）。
6. **设定**（R03 起）：设定集——时代卡（常驻）、地点、势力、物品、设定卡，可新建、编辑、删除；“AI 整理时代设定”；要点与叙事方针的编辑入口。见第 4.14 节。

编辑规则（第 6.4 节详述）：
- 面板中对**数值、物品、人物、目标和设定集卡片**的修改，生成一个隐藏的“修改节点”挂在当前回合之后，故事流中显示一行可折叠的小字（“你修改了：钱 100 文 → 120 文”）。撤销会撤掉修改；重说其前一回合时，程序会把修改自动沿用到新版本上（并提示“已沿用你的修改”）。
- **要点、叙事方针、文风与篇幅设置**属于整个世界，跨世界线保留（第 6.2 节）。

### 4.6 时间推进（R05）

- **时间显示**：顶栏显示朝代纪年（年号 + 年 + 农历月日 + 时辰），点开显示公历对照、节气、主角年龄、离开局过了多久。（纪年显示 R03，R02 先显示“第 N 日 · 时辰”；开局日期不明时仍用这种显示）
- **历法**（D119）：中国背景用简化农历（单月 30 天、双月 29 天、不设闰月），到改元月份时按本局的年号表换年号（来自内置卡组；自写的朝代没有年号表时一直往下数），过年时主角长一岁（虚岁）；西方背景用公历月长。
- **时间来源**：每回合记录块给出“过了多久”（如“半个时辰”，由程序换算）；缺少时按行动模式给默认值（做 15 分钟、说 5 分钟、继续 30 分钟）。程序累计并换算日期；模型不直接写日期。
- **“过些日子”**：⋯ 菜单打开选择：到明天 / 几天 / 一个月 / 一季 / 一年 / 直到有事发生；可选“这段时间做什么”（照常过日子 / 读书 / 经营 / 练武 / 自定义）。
- **快进产出**：一段“时光流逝”的叙述 + 一张**月报/邸报卡片**（天下风声、本地物价、人情往来）+ 状态变化（收入支出、年龄、健康、关系）。遇到需要主角决定的关键事件时提前停下，给出选项。
- **世界事件**：本局的大事年表（来自内置卡组，或由玩家、AI 写入）在游戏时间到达时进入月报和上下文；事件分“固定锚点”与“可变事件”，玩家的行动可能改变后者，改变时记入“历史偏离”。

### 4.7 叙事导演（设定页，R02 先提供篇幅与选项数）

- **叙事方针**（R04）：一段话，长期影响文风和节奏（如“节奏快一些，多写市井人物”）。
- **文风**（R03）：白话 / 半文半白；人称（第二人称“你”为默认）。
- **篇幅**（R02）：短（约 200 字）/ 中（约 400 字，默认）/ 长（约 800 字）。
- **选项数量**（R02）：0～4，默认 3。
- **难度**（R03 选择，R05 生效）：宽松 / 标准 / 残酷，影响运势分布和程序裁决严格度（D113、5.5）。
- **内容尺度**（R02 起，用户 2026-10-16 决定由玩家自行调整挡位）：分“暴力与伤亡”“感情与亲密”“黑暗与压抑”三项，每项三挡——**含蓄**（点到为止）/ **写实**（如实描写，不猎奇，默认）/ **浓烈**（尽量直接，仍受所用 AI 服务的规则限制）。开局时可选，游戏中在本局设置随时修改，下一回合生效。挡位写进系统规则；服务拒绝时按第 5.8 节处理。

### 4.8 世界线（R02 基础，R06 管理界面）

- **世界线**是一个会随着游玩前移的“当前位置指针”（类似 git 分支）；**书签**是固定不动的指针。
- 玩家在一条世界线上继续玩，它的指针跟着前进；“回到这里”“改我的行动”会从旧回合开出一条新世界线并切换过去，原来的世界线指针不动、内容完整保留。
- 为避免列表被刷满：离开的那条线如果在分叉点之后**不少于 3 个回合**，自动登记为“未命名路线”；更短的只作为“旧路线”在树视图里能找到，不进入列表。
- 世界线页面（R06）：列表（名称、最后一句、游戏时间、回合数）+ 简易树视图；可切换、重命名、归档、删除（回收站）。
- 切换世界线后，角色面板、人物志、目标等全部显示该世界线当时的状态。

### 4.9 查一查（R07）

- 游戏中随时提问“唐代一斗米多少钱？”“孙管事是什么人？”，不推进时间、不改状态。
- 先查本局资料（人物志、记事），再用模型知识回答，并标注“仅供参考”；联网搜索是后续可选项。

### 4.10 存档

- 每回合自动保存，没有“保存”按钮。
- 首页世界卡片：时代、主角、最后一句正文、游戏时间、回合数、上次游玩时间。
- 导出 / 导入单个世界（R08）；自动备份可设置到用户选择的手机目录（应用私有目录在卸载或清数据时会一起丢失，R08-T001）。

### 4.11 设置

- **AI 服务**（R02）：多个服务配置，可快速切换；每个配置有服务商、地址、Key、主模型、辅助模型；高级（温度、最大输出、上下文预算）默认按模型自动设置并折叠。
- **阅读**（R02）：字号、行距、主题（白天 / 夜间）；R09 增加字体、纸张主题、打字机效果等。
- **游戏默认**（R02 篇幅与选项数，R03 其余）：篇幅、选项数、难度、文风。
- **数据**（R08）：导出、导入、备份、用量统计与费用估算。
- **开发者模式**（R02 起，默认关闭）：原始模型输出、记录解析日志、调用日志、提示词版本；R04 增加上下文查看器。

### 4.12 文案原则

- 用玩家的话：说“这段没写出来，再试一次？”，不说“game_invalid_output，正式世界没有采用这段草稿”。
- 错误提示只说“发生了什么 + 玩家能做什么”，不解释内部机制。
- 不在游玩界面提示费用、协议、事务、操作 ID。
- 时代感文案可以用在过场、加载、月报里，但按钮和设置项保持现代、简洁、明确。

### 4.13 安卓专项交互

- **返回键**：依次关闭 弹层 → 面板 → 编辑状态 → 游戏页回首页 → 首页再按一次提示“再按一次退出”。使用 Tauri 的 `onBackButtonPress`（`@tauri-apps/api` 2.9+，项目当前 2.12.3）。**【待验证】** 项目 targetSdk 为 36，Android 16 默认启用预测性返回，需在手势导航与三键导航下都实测接管效果（R01-T005）。
- **输入法**：输入栏随键盘上移，正文不被遮挡（复用 v2 的窗口边距修复，D030）。
- **后台与中断**：Android 15+ 会在应用进入后台约 5 秒后切断其网络（2026-10-16 真机实测）。因此生成期间启动前台服务（通知“正在写下一段…”，写完自动消失，D116），Rust 端照常接收并把累计文字写入临时文件；回到前台或重新启动时从中补齐（第 7.3 节）。进程被系统杀死时，已写出的部分作为“已中断”回合保存，可续写或重说。
- **单手**：主要操作在屏幕下半部分；触控区不小于 44×44。

### 4.14 设定集：世界资料只有一个来源（R03，D121）

故事设定说明“这是个什么故事”；世界里的资料都放在设定集里，每样东西只存一处：

| 种类 | 内容 | 由谁建 | 何时交给 AI |
|---|---|---|---|
| 时代卡 | 每个世界一张：时局、货币与物价、称谓、日常与节令、文风、“不要出现”清单 | 内置卡组复制、AI 按故事设定整理、玩家自己写 | 每回合（常驻，1000 字以内） |
| 人物 | 就是人物表：身份、态度、生死、别名、备注 | 记账自动建，玩家可改 | 简表每回合；详情在场或被提到时（R04） |
| 地点 | 就是地点表：描述、别名 | 记账自动建、卡组预设、玩家建 | 身处其中或被提到时 |
| 势力、物品、设定 | 名称、别名（触发词）、正文 | 玩家建、AI 整理、卡组预设；R04 起 AI 在游玩中提议新卡 | 名称或别名出现在最近三回合或本次行动里时 |

- **常驻的只有三样**：故事设定、要点、时代卡。其余卡片按名字触发，不设“置顶”，免得和要点重复——必须一直记住的事写进要点。
- **行囊与物品卡分工**：行囊记数量和存放处（记账），物品卡写来历和用途（资料）；同名时物品卡随之触发。
- **规则不是卡片**：纪年（开局日期、农历或公历、年号表）、货币单位与换算、难度、内容尺度等由程序执行，放在“本局设置”。时代卡里只写钱怎么用、东西多少钱，换算以规则为准。
- **内置卡组**（原称“时代包”，格式见 D120）只是预设：开局时把时代卡、地点、年号表、货币和姓名复制进本局，此后以本局为准，玩家怎么改都不影响卡组。
- **AI 整理**：没选卡组时，开场生成的同时用辅助模型按故事设定整理时代卡和几张关键的势力、地点、设定卡（标“AI 整理”），只补故事设定没写的部分，不得与之矛盾；失败不影响开局，之后可在设定集里重新整理。
- 修改卡片和修改数值一样生成修改节点，可撤销；卡片属于状态快照，不同世界线各自独立。

## 5. AI 叙事引擎设计

### 5.1 回合流程

```
玩家行动（或继续 / 导演）
  → 组装上下文（5.3）
  → 主叙事调用（流式）
       ├─ 推理内容：不显示，界面显示“构思中…”
       ├─ 正文：逐字显示
       └─ 记录块：正文结束后出现，界面不显示原文
  → 判断是否被拒（5.8）
       └─ 被拒：不入树，显示“这段被服务拒绝了”与对策
  → 解析记录块（宽容，5.2）
       ├─ 成功：逐条校验并应用到状态（5.6）
       └─ 缺失/损坏：先显示正文，立即发起“补记”调用
            · 补记期间：输入栏显示“整理中…”，选项区只显示“继续”
            · 补记成功：应用记录，显示选项
            · 补记失败或超过 20 秒：本回合记为“无记录”，状态不变，提示可在面板手动修正
  → 一次事务保存回合节点（正文 + 记录 + 新状态快照 + 选项 + 用量）
  → 显示状态变化标签与选项
  → 达到摘要阈值时，后台生成章节摘要（R04，D106）
```

- 每个玩家回合**一次主调用**；补记、摘要是辅助调用（D107）。
- **补记只针对当前回合、在下一回合开始前完成**，绝不事后改写已有子节点的快照。
- 出第一个数据（推理或正文）之前的网络/服务错误自动重试 1 次；仍失败时，**玩家的行动文字放回输入框**，并显示失败卡片（“再试一次”“改一改”“换个服务”）。
- 出字后中断（断网、停止、被杀）：已写部分保存为“已中断”回合，提供“续写”和“重说”。
- 保存采用一次数据库事务写入整个节点，避免“正文有了、状态没了”。

### 5.2 回合输出格式（默认候选，最终由 V101 实验决定）

候选 A（默认）：正文 + 末尾标签包裹的紧凑 JSON。

```text
（正文，纯文本，若干段落）

<record>
{"time":"半个时辰",
 "place":null,
 "money":-2,
 "items":[{"name":"胡饼","delta":1}],
 "people":[{"name":"孙管事","role":"货栈管事","attitude":"冷淡","note":"答应明早再给活"}],
 "status":[{"op":"add","name":"脚踝扭伤","detail":"走路一瘸一拐"}],
 "goals":[{"op":"progress","name":"三日内还清三贯钱","detail":"已凑到一贯二百文"}],
 "log":"在西市货栈打短工，扭伤了脚",
 "risk":null,
 "choices":["去药铺看脚","回客栈歇息","再去问问孙管事"]}
</record>
```

- **期望每回合都有**：`time`、`log`、`choices`。其余字段缺省即“无变化”。
- `time` 接受“半个时辰”“两刻钟”“三天”“90分钟”等表达，程序换算成分钟；缺失或无法识别时按行动模式取默认值（4.6）。
- `money` 用时代最小货币单位（由时代包定义，如“文”），也接受“三贯”“二两银”这类表达，由程序按时代包换算。
- **名字匹配规则**（避免刷出重复人物和目标）：
  - 上下文中列出现有人物、物品、目标的**原名**，要求模型原样引用。
  - 人物与物品按“精确名 → 别名 → 规范化（去掉“子”“的”、全半角、空格等）→ 包含关系”依次匹配，都匹配不到才新建；新建时记录在开发者日志里。
  - 目标只有 `op: "add"` 才新建；`progress`、`done`、`fail` 匹配不到就丢弃并记日志。
- `choices` 缺失时（补记也没给出），选项区只显示“继续”。
- 流式显示时，程序检测到 `<record>` 开头后停止向界面输出，并正确处理标签被拆在两个数据块里的情况（缓冲末尾不足一个标签长度的字符）。

候选 B：正文 + 末尾逐行文本记录（如 `钱 -2文`、`得 胡饼 1`、`识 孙管事 货栈管事 冷淡`）。候选 C：只写正文，另发一次辅助调用提取记录。V101 实验比较三者（R01-T004）。

### 5.3 上下文组装

按以下顺序拼装，每层有预算；**总输入目标约 12k token，硬上限 14k**（设置中可调，按模型自动推荐）：

| 顺序 | 内容 | 默认预算 | 阶段 | 说明 |
|---|---|---|---|---|
| 1 | 系统规则 | ≤1.5k | R02 | 叙事者身份、写作原则（5.4）、记录块格式、硬规则 |
| 2 | 时代卡 | ≤1k | R03 | 设定集里的时代卡（常驻）：时局、货币与物价、称谓、日常与节令、文风、不要出现的东西；没有时代卡时只提醒“以故事设定为准” |
| 3 | 主角卡与当前状态 | ≤1k | R02 | 身份、数值档位、**可用钱数**、伤病、行囊（含数量）、所在地、时间 |
| 4 | 人物简表与进行中目标 | ≤0.8k | R02 | 全部已知人物各一行（名、身份、态度、生死）+ 在场人物详情 + 进行中目标 |
| 5 | 要点（常驻） | ≤0.5k | R04 | 当前世界线可见的要点 |
| 6 | 激活的故事卡 | ≤1.5k | R03（R04 完善） | 最近 3 回合正文与本次行动中出现名字或别名的地点、势力、物品、设定卡，加上当前地点 |
| 7 | 章节摘要 | ≤1.5k | R04 | 当前路径上、早于“最近原文窗口”的摘要，越近越详细 |
| 8 | 最近原文 | 余量 | R02 | 最近若干回合的玩家行动与正文，至少保留最近 3 回合 |
| 9 | 叙事方针与导演备注 | ≤0.3k | R02（导演）/ R04（方针） | 放在靠后位置，影响力更强 |
| 10 | 程序提示 | ≤0.2k | R02 | 上回合的裁决结果说明、本回合运势（R05） |
| 11 | 玩家行动 | — | R02 | 带模式标记：做 / 说 / 写 / 导演 / 继续 |

- 中文故事卡触发用**子串匹配**名字和别名即可，不需要分词；两字短名容易误触发的，用“全名优先 + 最近出现优先”处理。
- token 估算：先用保守估计（中文 1 字 ≈ 1 token），再用服务返回的实际用量校准比例；服务不返回用量时标为“估算”。
- 超预算时的取舍顺序：先削最近原文的早期部分（但保留 3 回合）→ 摘要压缩为更短版本 → 故事卡按最近提到的先后裁剪 → 时代卡截到上限。规则、主角状态、人物简表、要点、玩家行动永不裁剪。
- 开发者模式的上下文查看器（R04）显示每一层的内容、长度和“为什么被纳入”。

### 5.4 提示词原则

所有提示词放在 `src/engine/prompt/` 下，带版本号；每次修改记录版本并跑评测。

写作原则（写进系统规则）：
1. 第二人称“你”，现在进行时为主；先画面后解释，少用总结性句子。
2. **只写到玩家需要做决定为止**：不替玩家说话、不替玩家做行动之外的决定、不擅自完成玩家没说要做完的事（v2 评测中“先做一段”被写成做完整趟的教训）。
3. **“继续”时**主角只做等待、观察这类被动动作，由 NPC 和环境推动剧情。
4. 玩家行动有风险时，结果服从本回合运势（5.5）；失败也要写得有趣、有后果。
5. NPC 有自己的目的和情绪，不围着主角转；同一 NPC 的态度变化要有原因。
6. 称谓、钱币、计时、器物符合时代卡；拿不准的细节写得模糊些，不编造确切数字。
7. 涉及钱和物时，只能用上下文中“可用”的数量；正文写清数目，并与记录块一致。
8. 避免八股词与套话（黑名单示例：“指节泛白”“嘴角勾起一抹弧度”“眼中闪过一丝”“空气仿佛凝固”“心中五味杂陈”），避免重复上一回合的句式和开头。
9. 篇幅遵守设定；每回合结尾留出一个自然的行动点。

任务专用提示词：开场（4.2）、普通回合、继续、导演、快进（4.6）、补记、章节摘要、故事卡整理、查一查。

### 5.5 运势与挑战（R05，轻量“先裁定后叙事”）

- 每个回合由程序**事先**掷一次隐藏的“运势”（大顺 / 顺 / 平 / 不顺 / 大不顺），分布由难度决定（宽松偏顺、残酷偏不顺）。
- 运势绑定在**父节点**上：同一父节点下的重说沿用同一次运势；只有带“换个结果”方向的重说才重掷。
- 提示词告诉模型：“若玩家此次行动有风险或需要运气，结果倾向‘不顺’”；模型在记录块用 `risk` 字段说明是否用到了运势、用于什么（如“说服掌柜赊账”）。
- 用到运势时，回合下方显示一个小标签（如“🎲 不顺 · 说服掌柜”），让判定不再是黑箱。
- 不额外增加模型调用，延迟不变。

### 5.6 状态记账规则（D113）

| 数值 / 对象 | 存储与规则 |
|---|---|
| 钱财 | 以时代最小单位存整数；显示按时代换算（如唐“1 贯 200 文”、明“3 两 2 钱”）；宽松难度允许记为“欠款” |
| 健康 | 0～100，显示档位：康健 / 微恙 / 带伤 / 重伤 / 垂危；归零即死亡（宽松难度改为“昏迷”） |
| 精力 | 0～100，劳作、赶路消耗，休息恢复；显示档位 |
| 名望 | 0～100，按时代措辞显示（如“乡里风评”） |
| 物品 | 名称、数量、单位、存放位置、备注；数量不能为负；消耗即减少，转移只改位置 |
| 持续状态 | 伤病、增益等，有名称、描述、开始时间；解除时保留历史 |
| 人物 | 姓名、别名、身份、态度（仇视 / 敌意 / 冷淡 / 一般 / 友善 / 亲近 / 生死之交）、生死、备注、最近相见时间 |
| 地点 | 名称、描述；当前位置 |
| 时间 | 单调递增的分钟数 + 开局日期；不能倒退 |
| 目标 | 名称、类型（主线 / 支线 / 心愿）、进展、状态（进行中 / 完成 / 失败 / 放弃） |

不合法变化的处理（目标是让玩家**当场**看到一致的结果，而不是下一回合才改口）：
- 预防为主：每回合把可用钱数、物品数量写进上下文第 3 层，写作原则第 7 条要求只用可用数量。
- 钱不够：宽松难度记为欠款，显示“钱不够，赊欠 20 文”；标准/残酷难度按交易未成立处理，显示“钱不够，这笔没付成”，并在下一回合的程序提示中说明，由模型在叙事中圆回来。
- 物品不够：按实际可用数量扣减，显示实际结果。
- 无法修正的变化（如复活已死之人、时间倒退）：丢弃，记入开发者日志并在下一回合程序提示。
- 数值变化幅度有软上限（如单回合健康变化不超过 40，除非标记为重大事件），防止一句话把局面写崩。
- 主角死亡后本世界线结束，提供“回到某一回合”的入口。

### 5.7 模型服务适配

- 只对接 **OpenAI 兼容的 Chat Completions 接口**（覆盖 DeepSeek、通义千问、Kimi、智谱、硅基流动、火山方舟、OpenRouter、Gemini 兼容接口及各类中转）。服务商原生接口后置。
- **服务商预设**：内置常见服务的地址模板与推荐模型；用户可以填根地址（自动补 `/v1/chat/completions`）或完整地址。
- **模型列表**：调用 `GET /models` 获取，失败时允许手填。
- **主模型 / 辅助模型**：辅助模型用于补记、摘要、整理故事卡，可选更便宜的模型。
- **推理模型**：思考内容丢弃不显示（D027），界面显示“构思中…”；可选“关闭思考”参数以降低延迟（按服务商预设）。
- **超时**：第一个数据（推理或正文）等待 30 秒；任何数据（含推理）都会重置 30 秒的间隔计时；总时长 180 秒。可在设置调整。
- **用量**：首次连接测试时自动探测服务是否支持 `stream_options.include_usage`；不支持就不带该参数，用量改为估算并标明。
- **性能目标【待验证】**：首个正文字 ≤3 秒（取决于服务商与是否推理），中篇回合总耗时 ≤15 秒。R02 只记录不作门槛（V103）。

### 5.8 服务拒绝的识别与处理

- **硬信号**：HTTP 400 且错误信息含内容安全类字样、`finish_reason` 为 `content_filter` / `SAFETY` 等、正文为空。
- **软拒答**：没有记录块、正文少于 80 字、且命中拒答词表（“抱歉，我无法”“作为 AI”等）。
- 判为被拒时：不保存回合、不触发补记、不自动重试；显示“这段被服务拒绝了”，提供“改一改行动”“换个说法重说”“换个服务”。

## 6. 数据模型

### 6.1 存储方式

- 一个应用级 SQLite 数据库（开启 WAL），包含所有世界。浏览器开发台用同一套 SQL（sql.js），每次写入后防抖 1 秒持久化到 IndexedDB。
- 表结构迁移写成共享的 `.sql` 文件（如 `src/engine/db/migrations/001_init.sql`）：TypeScript 数据层在启动时按版本执行；Rust 的 `cargo test` 读取同一批文件跑冒烟用例，保证两端一致。迁移前自动备份数据库文件。
- 单个世界可导出为一个 JSON 包（含全部节点、快照、世界线、要点、章节），用于备份和迁移（R08）。

### 6.2 表

| 表 | 主要字段 | 说明 |
|---|---|---|
| `worlds` | id, title, era_id, current_line_id, settings_json（篇幅、选项数、文风、难度、叙事方针）, created_at, updated_at, played_at, archived | 世界；世界级设置跨世界线保留 |
| `nodes` | id, world_id, parent_id, last_child_id, kind（opening / turn / continue / direct / fastforward / edit）, action_mode, action_text, director_note, narrative, record_json, choices_json, status（ok / interrupted / no_record）, rewritten, fate, meta_json（模型、用量、耗时、提示词版本）, created_at | 回合树节点；`last_child_id` 供“重做”使用；`edit` 节点没有正文，只有记录（修改补丁） |
| `states` | node_id, state_json, size | 每个节点的完整状态快照，单独存表；读取故事流时不加载 |
| `lines` | id, world_id, name, node_id, kind（line / bookmark）, auto_named, archived, created_at | 世界线（随游玩前移的指针）与书签（固定指针） |
| `pins` | id, world_id, origin_node_id（可为空）, text, created_at | 要点；`origin_node_id` 为空表示全局要点；不为空时只在该节点位于当前路径上时生效 |
| `chapters` | id, world_id, first_node_id, last_node_id, summary, model, prompt_version, created_at, edited | 章节摘要；只有当 `last_node_id` 在当前路径上时才使用（R04） |
| `templates` | id, kind（opening / persona）, name, json, created_at | 开局模板、人物模板（R03） |
| `usage` | id, world_id, node_id, purpose（turn / opening / extract / summary / ffwd / ask / test）, profile_id, model, prompt_tokens, completion_tokens, estimated, first_token_ms, total_ms, outcome, at | 调用用量 |
| `profiles` | id, name, provider, base_url, main_model, aux_model, params_json, key_slot, capabilities_json | AI 服务配置（Key 本身在平台加密存储，这里只存槽位名） |
| `settings` | key, value | 阅读、游戏默认等应用级设置 |

### 6.3 状态快照（`states.state_json`）

```text
WorldState {
  version
  time: { date(开局日期), start(文字说法), startHour, elapsedMinutes }
  placeId
  protagonist: { name, aliases, age, gender, identity, origin(原本是谁), cheat(金手指),
                 stats: { money, debt, health, energy, fame }, statuses[], items[] }
  people[]   // 设定集的人物卡：id, name, aliases, role, attitude, alive, notes, lastSeenMinute
  places[]   // 设定集的地点卡：id, name, aliases, description
  cards[]    // 设定集的其余卡片：时代（每个世界一张，常驻）、势力、物品、设定（D121）
  goals[]
  era: { packId, calendar, currency }   // 来源卡组（只作记录）、纪年规则、货币规则
  deviations[]                 // 历史偏离记录（R05）
  ffwd: { pausedDecision? }    // 快进中断点（R05）
}
```

- 快照预计每回合几 KB 到几十 KB；1000 回合的世界在几十 MB 以内（D105）。超过阈值时再考虑差量存储。
- 要点、叙事方针、文风篇幅等世界级内容**不在快照里**（见 `pins` 与 `worlds.settings_json`）。

### 6.4 路径、世界线与编辑规则

- **当前路径** = 从当前世界线指针沿 `parent_id` 走到根（用递归 CTE 一次取出）。组装上下文、显示故事流、选用章节摘要与要点，都只看当前路径。
- **继续游玩**：新节点挂在指针所指节点下，指针前移，父节点的 `last_child_id` 指向新节点。
- **重说**：在同一父节点下生成兄弟节点，指针移到新兄弟；‹ › 切换版本即在兄弟间移动指针。若被重说的回合之后紧跟着玩家的修改节点，程序把同样的修改补丁自动挂到新版本之后（并提示“已沿用你的修改”）。
- **撤销 / 重做**：撤销把指针移到父节点；重做沿 `last_child_id` 前进。不删除节点。
- **回到这里 / 改我的行动**：从目标节点开出一条新世界线并切换过去；原世界线指针不动。原线在分叉点之后不少于 3 个回合的，自动命名为“未命名路线”进入列表；否则只在树视图中作为旧路线可见。
- **面板编辑**：生成 `edit` 节点（记录 = 修改补丁，用与记录块相同的操作词表），挂在当前节点下，指针前移。
- **改写正文**：直接修改该节点的 `narrative` 并标记 `rewritten`；不影响状态快照。
- **删除**：只在世界线管理中进行（R06）。删除一条世界线时，只删除不被其他世界线、书签、要点引用的节点，先进入回收站。

### 7.3 Platform 接口

```ts
interface Platform {
  sql: {
    query(sql: string, params?: unknown[]): Promise<Row[]>;
    batch(statements: { sql: string; params?: unknown[] }[]): Promise<void>; // 单事务
    backup(label: string): Promise<string>;           // 复制数据库文件，返回备份名
    listBackups(): Promise<{ name: string; at: string; size: number }[]>;
  };
  secrets: {
    set(slot: string, value: string, boundBaseUrl: string): Promise<void>; // Key 绑定到服务地址前缀
    has(slot: string): Promise<boolean>;
    remove(slot: string): Promise<void>;
  };
  llm: {
    // 平台在内部读取 slot 的 Key 并加到请求头；url 必须以该 slot 绑定的地址开头，否则拒绝。
    // 平台把累计文本缓存到私有临时文件，供后台恢复与进程重启后补齐。
    stream(req: { slot: string; url: string; body: unknown; timeouts: Timeouts },
           onEvent: (e: { type: "data"; data: string } | { type: "done" } |
                        { type: "error"; kind: string; status?: number; message?: string }) => void
    ): { streamId: string; cancel(): void };
    resume(streamId: string): Promise<{ data: string[]; done: boolean; error?: string } | null>;
    listUnfinished(): Promise<string[]>;              // 启动时找回中断的生成
    get(req: { slot: string; url: string }): Promise<{ status: number; body: string }>;
  };
  files: {
    exportText(suggestedName: string, text: string): Promise<boolean>;
    importText(): Promise<string | null>;
  };
  system: {
    onBack(handler: () => boolean): () => void;       // 返回 true 表示已处理
    onResume(handler: () => void): () => void;        // 回到前台
    platformName: "android" | "windows" | "web-dev";
  };
}
```

- SSE 的 `data:` 行由平台**原样**转交，**解析在 TypeScript 里统一做**，两种实现共用同一个解析器；未知字段一律忽略，不报错。
- 后台恢复：界面回到前台（`onResume`）或启动时（`listUnfinished`），引擎调用 `resume` 补齐错过的数据；进程被杀导致的未完成生成，按“已中断”回合处理。
- **浏览器开发实现**：`sql` 用 sql.js（防抖持久化到 IndexedDB，`backup` 存为 IndexedDB 中的副本）；`secrets.set` 把 Key 交给开发服务器，保存在本机不入 Git 的 `.cache/dev-secrets.json`，`.env.local` 只用于预填；`llm` 走开发服务器上的自写转发中间件（按 slot 注入 Key、按请求转发到目标地址、关闭压缩并逐块转发、只监听 127.0.0.1）。仅用于开发。

### 7.4 Rust 平台服务

- **SQL 桥**：基于 rusqlite（v2 已验证可在 Android 运行）；`sql_query`、`sql_batch`（事务）、`sql_backup`；数据库文件放在应用私有目录。
- **密钥**：复用 v2 的 Android Keystore 与 Windows DPAPI 实现；增加“绑定地址前缀”；对外只有 set / has / remove。
- **模型传输**：复用 v2 的 HTTP 客户端、有界读取、超时、取消和“回显 Key 过滤”；**删除 v2 `stream.rs` 中的 delta 字段白名单与载荷校验**（约第 650～730 行，遇到未知字段即报错），改为按行原样转发 `data:`；累计文本写入私有临时文件；支持用户明确勾选的 HTTP（D026）。
- **文件**：复用 v2 的 Android 文档选择器与内容 URI 读取；Windows 用系统对话框。
- **系统**：返回键（`onBackButtonPress`，需要 `core:app` 相应权限声明）、前后台事件。
- 其余 v2 Rust 代码（游戏协议、存储、分支、研究、调用台账、恢复探针等）全部移除，可从标签 `legacy-v2-final` 查阅。

### 7.5 依赖选择原则

- 新增依赖要有明确收益，并在任务里记录原因。预期需要：`sql.js`（开发台与评测）、`vitest`（测试）、一个农历库（R03 评估 `lunar-javascript` 等，【待验证】其支持的历史年份范围）、R08 评估虚拟列表库。

## 8. 开发方法与质量保障

### 8.1 开发回路（D108）

- **日常**：`pnpm dev` 打开浏览器，切换到手机尺寸（393×852 和 360×800 两种），用真实模型直接游玩调试。

### 8.2 测试分层

| 层 | 内容 | 工具 | 要求 |
|---|---|---|---|
| 引擎单元测试 | 记录块解析（含各种畸形输入、标签跨分片）、记账规则、名字匹配、回合树操作、上下文预算、历法货币换算、拒答识别 | vitest | 每次提交前通过 |

| Rust 平台测试 | SQL 桥事务、流式转发（未知字段不报错）、取消、缓存与恢复、密钥地址绑定 | cargo test | 改动 Rust 时通过 |

### 8.3 模型评测指标

评测脚本在 Node 中直接运行引擎（Platform 用内存 sql.js + 直连模型），按剧本或“自动玩家”（让一个便宜模型扮演玩家）推进若干回合，输出报告到 `docs/validation/`（摘要）和 `.cache/eval/`（原始数据，不入 Git）。框架在 R01-T004 建立，R02-T014 扩展。

| 指标 | 定义 | 目标（初值，可调） | 是否门槛 |
|---|---|---|---|
| 回合成功率 | 正文非空且完整；**剔除服务方 5xx/429 与网络故障**后统计 | ≥ 98% | R02 起 |
| 记录块解析率 | 记录块存在且能解析 | ≥ 95%（其余靠补记） | R02 起 |
| 补记后状态覆盖率 | 补记后有记录的回合比例 | ≥ 99% | R02 起 |
| 数值冲突率 | 程序修正/丢弃的变化占全部变化的比例 | ≤ 5% | R02 起 |
| 重复新建率 | 同一人物/目标因换说法被重复新建的次数 / 百回合 | ≤ 2 | R02 起 |
| 首字延迟、回合总耗时 | 发出请求到第一个正文字；中篇回合 | 首字中位数 ≤ 3 秒、总耗时中位数 ≤ 15 秒【待验证】 | 只记录（取决于服务） |
| 输入 token | 每回合 | 目标 12k，硬上限 14k | R04 起 |
| 八股词频率 | 黑名单词出现次数 / 千字 | ≤ 0.5 | R02 起 |
| 抢话率 | 评审模型判定“替玩家说话或做决定”的回合比例 | ≤ 5% | R02 起 |
| 记忆探针 | 在第 N 回合询问/触发早期事实，判定是否正确 | ≥ 90% | R04 起 |
| 体验评分 | 评审模型按“代入、时代感、节奏、人物”1～5 分 | 平均 ≥ 4 | 只作参考 |

### 8.4 试玩问卷（每阶段）

用户在手机上玩 20～40 分钟后填写（模板见[问卷模板](validation/PLAYTEST_TEMPLATE.md)）：流畅、代入、好操作、记得住、想继续玩各 1～5 分，加最喜欢、最难受、最想加的一点。

- R02、R03 还没有完整记忆系统，“记得住”只记录、不计入平均分门槛。

| 第三方中转服务不稳定（v2 期间出现过 403、401、503） | 无法游玩 | 支持多个服务配置快速切换；错误提示说清楚是服务问题；建议准备一个备用服务 |
| 模型不遵守记录块格式 | 状态缺失 | 宽容解析 + 同步补记 + 手动修正；V101 选最稳的格式 |
| 模型换说法导致重复人物、目标 | 面板混乱、失忆 | 名字匹配规则（5.2）；评测统计重复新建率 |
| 服务安全过滤拒绝战争、暴力情节 | 剧情中断 | 识别硬信号与软拒答（5.8），友好提示改写或换模型；不自动绕过 |
| 长故事在手机 WebView 中卡顿 | 体验差 | R02 起只渲染最近 30 回合 + 加载更早；R08 评估虚拟列表 |
| 安卓后台暂停 JS、杀进程 | 丢一回合 | Rust 端缓存流式文本并支持恢复（7.3）；R08 真机验证 |
| Android 16 预测性返回与 `onBackButtonPress` 不兼容 | 返回键直接退出 | R01-T005 实测；不行则在 Kotlin 侧注册返回回调转发 |
| 简化农历与真实历法有出入 | 某天的朔望、节气对不上 | D119 已取舍：只保证纪年、月份与经过时间一致；需要考据时再评估 |
| 时代卡内容不准确（卡组或 AI 整理） | 出戏、被考据党挑错 | 内置卡组标注来源与可信度并抽查；AI 整理的卡标“AI 整理”；玩家可在设定集里直接修改 |
| 设定集与故事设定、要点重复或矛盾 | AI 收到互相打架的资料 | 每类资料只存一处（第 4.14 节）；AI 整理只补故事设定没写的部分，并以故事设定为准 |
| 小米手机无法 ADB 安装 | 真机迭代慢 | 浏览器开发台承担大部分调试；按 V102 尝试开关；保留手动安装流程 |
| 浏览器开发台与 Android 行为差异 | 返工 | 输入法、返回键、后台、字体等必须真机验收 |
| 范围膨胀 | 迟迟没有可玩版本 | 严格阶段门槛；新想法先进台账“候选池”，不插队 |
| 用户试玩时间有限 | 阶段卡住 | 问卷简短；可以两个阶段合并一次试玩 |
| 费用超出预期 | 不敢玩 | 上下文预算、辅助模型、用量统计；必要时加每日上限 |

### 11.3 吸收的经验（写入评测探针）

- 时间单位：“一刻”= 15 分钟，“半个时辰”= 60 分钟，“一个时辰”= 120 分钟；模型常算错，所以由程序换算。
- 动作范围：玩家说“先做一段”，模型容易写成做完整件事并结算。
- 正文写了“放下行囊”，状态却没记位置变化。
- 具体条件（“明早按件两文”）在概括时丢失。
- 时代细节（“算盘”是否出现在唐代）需要时代包与禁忌清单支持。

## 12. 术语表

| 术语 | 含义 |
|---|---|
| 回合 / 节点 | 玩家一次行动及 AI 的一段叙事；存储上是回合树中的一个节点 |
| 回合树 | 一个世界全部回合组成的树；重说、分支、回到过去都是树上的操作 |
| 世界线 | 一个随游玩前移的“当前位置指针”，及其到根的路径 |
| 书签 | 固定不动的指针，用于收藏某一回合 |
| 旧路线 | 离开后未登记为世界线的分支，只在树视图中可见 |
| 修改节点 | 玩家在面板中修改数值、物品、人物、目标时生成的隐藏节点，内容是修改补丁 |
| 记录块 | 模型在正文后附带的选项与状态变化，玩家看不到原文 |
| 补记 | 记录块缺失或损坏时，在下一回合开始前从正文提取状态变化的辅助调用 |
| 状态快照 | 某个节点时刻的完整世界状态 |
| 设定集 | 一个世界的全部资料：时代卡、人物、地点、势力、物品、设定（第 4.14 节） |
| 故事卡 | 设定集里的一张卡；时代卡常驻，其余按名字或别名触发进入上下文 |
| 要点 | 玩家记下、每回合都带上的重要事实；可以是全局的，也可以只属于某段剧情 |
| 章节摘要 | 每若干回合自动生成的剧情压缩 |
| 叙事方针 | 长期影响文风和节奏的一段指示（类似 Author's Note） |
| 导演 | 只影响本回合写法的幕后指令，可单独发送或附在行动上 |
| 时代卡 | 设定集里描述时代的那张常驻卡：时局、货币与物价、称谓、日常节令、文风、不该出现的东西 |
| 内置卡组 | 原称“时代包”：整理好的某个时代的资料（时代卡、地点、年号表、货币、身份模板、大事），开局时复制进本局 |
| 运势 | 程序每回合事先掷出的隐藏结果倾向，用于有风险的行动 |
| 开发台 | 在电脑浏览器以手机尺寸运行游戏的开发模式 |
| 主模型 / 辅助模型 | 写正文的模型 / 做补记、摘要等后台任务的模型 |
