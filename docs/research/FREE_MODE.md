## 一句话结论

> 2026-10-17 按用户意见收窄：项目对内容的规定已经太多，异世界模式要做“减法”。不内置修为境界、等级、系统任务这类机制，也不把它们做成必选模块；世界交给玩家或 AI 写的一张世界卡（设定文字），其余全靠现有的通用记账（记忆、人物、物品、时间）。任何额外机制都只能是可选、默认关闭，并且要说得出具体给玩家带来什么好处。

1. **成熟产品基本都用同一套骨架装下所有题材**：一段常驻的“世界设定”（AI Dungeon 的 Plot Essentials / AI Instructions、SillyTavern 卡片的 description/scenario、彩云小梦的“故事背景”），加按关键词触发的资料卡（Story Cards、Lorebook / World Info、世界书），再加一个开场。题材本身不是程序概念，只是一段预先写好的文字。我们已经有完全对应的东西：故事设定、要点、时代卡（常驻），加设定集卡片（按名字触发）。**所以异世界模式几乎不需要新引擎，要做的是把历史专用的规则关掉、换成中性的说法。**
2. **境界、等级、系统任务都可以写进世界卡和故事设定里，由 AI 按文字执行。** 现有记账已经记了人物、物品、钱、伤病、目标和时间：“筑基丹”是一件物品，“三天内完成系统任务”是一个支线目标，“灵石”是一种货币。LitRPG 写作圈确实提醒过数字容易前后对不上，但这只对爱看数值的玩家要紧。本提案不做内置机制，只留一个默认关闭的可选项（“主角面板”，见 5.4），等试玩发现真有需要再说。
3. **历史模式里有一组规则必须在异世界模式下关掉**，见 5.1 的清单。关掉之后，游戏除了“叙事者不再假定是真实历史”之外，行为和现在一样。
4. **版权上，内置内容一律原创**：不内置任何作品的人物名、设定名或剧情；知名作品世界只能由玩家自己写或粘贴，数据只存在本机。国内判例（金庸诉江南，2023）认定足够具体、相互关联的人物群像本身受保护；奥特曼案（2024）要求生成式服务对权利人投诉做关键词过滤。我们是本地运行、玩家自带 Key、不分享内容的个人工具，风险远小于平台，但**不内置、不分享“同人世界包”**是必须守住的底线。
5. **开局**：现有作者模式的开局页加一个“历史 / 异世界”切换和一排精简的题材模板（约 10 个，各配一句钩子），外加“随便穿”和“一句话想法 → AI 写世界卡”。不另做第二套流程。

## 一、别人怎么做开放题材的世界

### 1.1 海外

| 产品 | 世界怎么定义 | 题材怎么处理 | 结构化状态 | 对我们的启发 |
|---|---|---|---|---|
| **AI Dungeon**（Latitude） | 剧本（Scenario）＝开场 Prompt ＋ Plot Components（AI Instructions、Story Summary、Plot Essentials、Author's Note，常驻）＋ Story Cards（按触发词进上下文）；`${问题}` 占位符向玩家提问 | 题材不是字段，靠剧本文字和社区剧本；Story Card 有类型（角色、职业、种族、地点、势力、自定义） | 本体没有属性背包，靠脚本；Voyage 改为确定性世界引擎管 HP、物品、货币 | 骨架和我们一致；Story Card 生成器用“`{{title}}` + 类型”让 AI 写卡；卡片可导入导出 |
| **NovelAI** | Memory、Author's Note、Lorebook（关键词、`&` 组合、正则、Always On） | Lorebook 生成器按“生成类型”写条目，输入名字加括号标签（如“Black Skull Fleet (pirates, space)”） | 无 | “名字＋一两个标签”就够 AI 写好一张卡，可用于异世界的快速建卡 |
| **SillyTavern / RisuAI / chub.ai** | 角色卡 V2/V3（name、description、personality、scenario、first_mes、alternate_greetings、system_prompt、character_book…）＋ 独立的 World Info（Lorebook） | 卡片社区按标签分类；“世界卡”就是一张没有固定人设、写满世界观的卡 | 核心没有；RisuAI 用触发脚本和变量做状态栏 | **卡片格式是事实标准**，chub.ai 等社区以 PNG/JSON 分发；支持导入 `character_book`/World Info 的条目（keys→别名、content→正文）就能吃下大量现成世界书 |
| **SillyTavern World Info 细节** | 扫描深度、递归激活、概率、互斥组、粘滞（sticky，触发后保持 N 条）、冷却 | — | — | “粘滞”值得借鉴：异世界的势力卡、功法卡被提到一次后应多留几回合【待验证】 |
| **KoboldAI Lite** | Memory、Author's Note、World Info，内置冒险模式和一批剧本 | — | 无 | 与上同 |
| **Infinite Worlds** | 世界 JSON：background、firstInput、objective、instructions / instructionBlocks（常驻）、loreBookEntries（关键词）、NPCs（含 secret_info）、**trackedItems**（名字、类型、可见性、更新说明、初始值）、**triggerEvents**、victory/defeat 条件、**skills（0–5 级）** | 世界生成器从一句话生成 3–5 个技能、3–4 个可选主角 | 技能 0–5 级参与成败判定；“被追踪的项目”由 AI 按更新说明自动改 | **“被追踪项”是通用解法**：不为每个题材写代码，而是让世界声明“要追踪什么、怎么变”；技能 0–5 级加文字档位很适合手机 |
| **Friends & Fables** | 世界构建器：地图、角色、种族、职业、势力、怪物、物品、法术、任务、Lore；Franz 先“研究”再叙事 | 以 D&D 5e 为底，也有科幻、赛博世界 | 5e 战斗、属性、背包由程序管；状态更新交给另一组模型后处理 | 状态更新与叙事分开调用；我们的“记录块＋记账”已是轻量版 |
| **AI Roguelite** | 描述起始宇宙（如“underwater city”），AI 生成地点、NPC、敌人、物品、合成配方 | 一句话即一个题材；支持跨世界、跨宇宙旅行 | 属性、技能、物品稀有度、可堆叠物品、等级、队伍 | **稀有度与堆叠**是 RPG 玩家的基本期待；“跨宇宙旅行”就是无限流的雏形 |
| **Dreamjourney** | 角色/故事 Bot ＋ Lorebook ＋ Memory Nexus（自动维护人、地、物条目，标出改动，可编辑、锁定、撤销） | 社区里大量同人世界（Prythian、Wizarding World、Naruto、Pokémon…）和原创“Fantasy Isekai”“Write Your Own Story” | 无 | 同人世界是用户创作的大头；“Fantasy Isekai：故事由你决定”这类**万能开局**也是最热门的条目之一 |

### 1.2 国内

| 产品 | 世界怎么定义 | 对我们的启发 |
|---|---|---|
| **星野**（MiniMax） | 智能体（基础设定公开、高级设定隐藏）＋“故事”（同一智能体的多个剧本，可设故事目标与达成条件）；“挑战模式”用好感度等数值推进章节 | “公开设定 / 隐藏设定”对应我们“玩家看得到的设定集 / 只给 AI 的秘密”【待验证是否需要】；数值推进章节是轻量的“系统任务” |
| **猫箱**（字节） | 故事设定、角色、开场白；**AI 创作助手一问一答**引导完成；多张图以上的故事要求写世界观、章节结局 | 一问一答比空白表单好上手，适合“从一句话生成世界” |
| **筑梦岛**（阅文） | “世界观”玩法：一个世界观下可挂多个角色，用“小剧场”写剧情线；角色多来自网文、游戏、动漫 | 网文读者天然以“世界观”为单位思考；同人是主力内容 |
| **彩云小梦** | 世界设定：300 字以内故事背景 ＋ 普通词条 ＋ 人物词条 ＋ 人物关系；世界广场公开后显示引用数 | 我们的“故事设定＋设定集”已经覆盖；300 字背景说明玩家写不了太长，AI 要能补 |
| **豆包剧情类玩法** | 依托猫箱/豆包的剧情互动；本次没有找到独立的创作规范文档【待验证】 | — |
| **刀锋 Blade RPG · 大千世界**（台湾） | 用白话写“世界观法则、开局身世、状态栏”，AI 当 DM；可自定义状态栏和“主角开局能力” | 公开世界里**同人改编最多（87 个），其次都市、仙侠、武侠、西幻、科幻、无限流**；说明题材分类和用户需求顺序；“自定义状态栏”就是通用追踪项 |
| **MissAI、叙界等新产品** | 八大题材、原创模块；叙界明确“为规避版权，优先原创模板和用户本地上传材料，不内置未授权 IP” | 与我们的版权立场一致 |

### 1.3 网文平台的题材分类（用来定我们的题材网格）

- **起点中文网**一级分类：玄幻（东方玄幻、异世大陆、王朝争霸、高武世界）、奇幻（剑与魔法、史诗奇幻、现代魔法…）、武侠（传统武侠、武侠幻想、国术无双…）、仙侠（修真文明、幻想修仙、现代修真、神话修真、古典仙侠）、都市（都市异能、异术超能…）、科幻（星际文明、时空穿梭、进化变异、末世危机…）、悬疑灵异（诡异神秘、**规则怪谈**…）、**诸天无限**、游戏（虚拟网游、游戏异界、游戏系统）、轻小说（含衍生同人）。
- **番茄小说**热门标签（在读量）：**系统**（1.7 亿）、**重生**（1.2 亿）、都市、玄幻、末世、快穿、修仙、都市高武、**魂穿**、无限流、同人、**穿书**、诸天万界、灵气复苏、规则怪谈等。
- 结论：题材网格按“世界类型”分（仙侠/玄幻/武侠/西幻/异世界/科幻/末日/都市异能/悬疑怪谈/同人），**“系统、重生、穿书、快穿、无限流”不是世界类型，而是叠加在任何世界上的“玩法外挂”**——首版把它们写成模板和世界卡的文字，不做成程序机制（见第五节）。

## 二、各题材需要什么机制

### 2.1 逐题材拆解

| 题材 | 读者/玩家期待的“爽点” | 需要的叙事元素 | 需要程序记的数字 |
|---|---|---|---|
| **仙侠/修真** | 突破境界、越级而战、寿元压力、机缘与天劫 | 境界阶梯（常见：炼气→筑基→金丹/结丹→元婴→化神→炼虚→合体→大乘→渡劫，各分初中后期与大圆满）、灵根资质、宗门势力、丹药法宝、灵石货币 | **境界与小阶段**、修为进度、灵石；可选寿元 |
| **玄幻/高武** | 等级碾压、血脉觉醒、打脸 | 自创的力量等级（同类作品各不相同，同质化是读者痛点）、王朝/家族 | 等级阶梯 |
| **武侠** | 武功招式、门派恩怨、内力 | 门派、武学（招式而非数值）、江湖名望 | 可选：武学清单、内力档位 |
| **日式异世界 / 西幻** | 状态窗口、技能、冒险者公会、升级 | 职业、技能、公会等级、魔物、魔法体系 | **等级＋经验**、属性（可选）、技能清单、公会等级、金币 |
| **系统流** | 签到、任务、奖励、商城 | 系统人格（冷漠/毒舌/拟人）、任务、奖励、惩罚 | **系统点数、任务列表（含奖励与期限）**、兑换记录 |
| **穿书/穿剧** | 知道剧情并改变它、避开炮灰结局、OOC 风险 | 原著剧情节点、原主人设、男女主光环、“剧情惯性” | **原著节点清单（已发生/已改变/未到）**、可选“偏离度” |
| **快穿** | 一个世界一个委托、换身份逆袭 | 委托人心愿、世界切换、系统空间 | 当前任务世界、委托完成度、积分 |
| **无限流** | 副本求生、主神空间、积分兑换、队友 | 主神/系统、副本规则与通关条件、团队 | **积分、当前副本与通关条件、兑换物** |
| **科幻 / 星际** | 科技、舰船、文明冲突 | 势力、科技树、星图 | 可选：信用点、舰船状态 |
| **末日 / 废土** | 资源匮乏、据点、异能进化 | 丧尸/灾变规则、据点、物资 | **物资（食物、水、弹药）**、异能等级、据点人数（可选） |
| **都市异能 / 灵气复苏** | 隐藏身份、能力觉醒、现代生活与超凡冲突 | 能力规则、管理组织、现代社会 | 能力等级（可选） |
| **规则怪谈 / 悬疑** | 破解规则、理智 | 规则条目（真假混杂）、线索 | 可选：理智值、已知规则清单 |

来源依据：修仙境界体系见百度百科“修炼体系”、凡人修仙百科与多个设定站；系统流、快穿、无限流的结构见红袖读书/QQ 阅读百科对《炮灰女配的无限逆袭》《快穿炮灰逆袭花样攻略》等作品的设定解析，以及钛媒体对无限流“系统＋场景＋人物”结构的总结；穿书的“剧情偏离值监测”“原著剧情点”见多部穿书作品百科。这些是同人百科性质的页面，只用来确认“套路存在且常见”，不作为权威定义。

### 2.2 哪些只靠设定卡和提示词，哪些要结构化状态

> 这是调研结论，不是要做的功能。按用户意见（2026-10-17），首版全部靠世界卡、故事设定和现有记账完成；右栏“需要结构化状态”的内容只作为将来的可选候选，默认关闭（见 5.4）。

判断标准（来自 LitRPG 写作圈和 v3 已有的记账经验）：**会被玩家数、会被拿来比较、会被消耗或在跨很多回合后必须准确的，交给程序；描述性、氛围性的，交给卡片。**

| 元素 | 卡片＋提示词就够 | 需要结构化状态 | 理由 |
|---|---|---|---|
| 世界观、力量体系说明、境界名称表、魔法规则 | ✔ 世界观卡/设定卡 | — | 只是“这个世界怎么运作”，模型读懂即可 |
| 门派、公会、王国、组织 | ✔ 势力卡 | 可选：声望值 | 现有势力卡已能触发 |
| 功法、法宝的来历和效果 | ✔ 物品卡/设定卡 | — | 现有“行囊记数量、物品卡写来历”的分工照用 |
| **主角当前境界/等级与进度** | — | ✔ | 最常被问“我现在什么境界”；突破是关键事件，必须一致 |
| **技能/武学/异能清单** | 可以先放卡片 | ✔ 推荐 | 技能会被反复使用、升级；放卡片容易被模型忘或改名 |
| **系统点数、积分、灵石** | — | ✔ | 和“钱”同类，可复用现有货币与记账 |
| **系统任务（目标、奖励、期限）** | — | ✔ | 可复用现有“目标”（主线/支线/心愿），加奖励与期限字段 |
| **物品稀有度/品阶** | — | ✔ 轻量 | 只是物品多一个字段；RPG 玩家强期待 |
| **原著剧情节点** | — | ✔ | 复用“天下大事”（固定/可变）和“改史记录” |
| 属性（力量、敏捷…） | — | 可选 | 很多玩家反感照搬网游面板（见[中文调研](COMPETITORS_CN.md#三穿越题材玩家想要什么)），默认关 |
| 理智值、饥饿、物资 | — | 可选 | 末日、怪谈题材才开；可用“通用计量条”实现 |

## 三、同人与知名作品世界：法律与实际做法

### 3.1 公开判例和平台做法

- **金庸诉江南《此间的少年》案**（广州知识产权法院，2023 年终审）：情节不构成实质性相似，但“郭靖、黄蓉、乔峰、令狐冲等 60 多个人物组成的人物群像”，在名称、性格、关系、背景上“足够具体到形成一个内部各元素存在强烈逻辑联系的结构”，属于受保护的表达，构成著作权侵权；副标题“射雕英雄的大学生涯”蓄意关联，另构成不正当竞争。判赔 188 万元，未判停止发行但再版须付版税 30%。研讨会上学者意见分歧很大（王迁认为只用名称和简单性格属于标识性使用），但判决结果是现行最直接的参考。
- **奥特曼案**（广州互联网法院，2024，生成式 AI 服务侵权首案）：平台对用户能生成与奥特曼实质性相似的图片承担责任；法院要求采取关键词过滤等措施，使“用户正常使用与奥特曼相关的提示词”时不再生成侵权内容，并建立投诉举报机制、风险提示。
- **Disney 对 Character.AI 的停止侵权函**（2025-09）：Character.AI 删除了用户创建的 Disney 角色机器人，并表示“规则由权利人决定，收到投诉迅速删除”。
- **AI Dungeon 服务条款**（2026-04 修订）：禁止用服务创作侵犯第三方知识产权的内容，包括“受版权保护的角色、商标品牌”，并明确“这适用于你输入的内容和 AI 返回的内容”；按 DMCA 处理投诉。但实际社区里同人剧本大量存在（Dreamjourney 同理），平台以“用户负责＋通知删除”应对。
- **叙界**（国内参赛作品）：明确“优先原创模板和用户本地上传材料，不直接内置未经授权的 IP 世界”。

### 3.2 对我们意味着什么

我们和上述平台的根本区别：**本地运行、玩家自带 AI 服务和 Key、没有账户、没有社区、不托管玩家内容**。玩家在自己手机上写一个同人世界给自己玩，接近私人阅读与创作；风险主要在“我们分发了什么”。据此建议：

1. **内置内容一律原创**：模板、示例、提示词、截图、商店介绍里不出现任何现存作品的书名、人物名、专有设定名（如具体门派名、魔法学校名、角色名）。题材用通用词（“修仙”“魔法学院”“末日丧尸”），**不写“XX 风格”**。
2. **不内置、不分享“同人世界包”**：不做 IP 世界的卡组，不做在线世界广场。将来若做“分享世界”（例如导出文件给朋友），在导出时提醒“含他人作品元素的世界仅供个人使用”。
3. **知名作品世界只由玩家提供**：三种方式——(a) 只填“作品名＋我是谁”，让模型用自己的知识（标明“AI 记得的原作可能有误”）；(b) 粘贴自己写的摘要或百科式简介，由 AI 整理成卡片（只存整理结果，不鼓励大段粘贴原文；可设长度上限，见 5.6）；(c) 导入社区世界书文件。三种都只存在本机。
4. **不做关键词屏蔽**：奥特曼案的过滤义务针对的是收到投诉的生成式服务提供者；我们不提供模型、不托管生成，引入屏蔽会伤害正常使用【待验证：如果将来上架应用商店或公开分发，再请专业人士评估】。
5. **分享卡片、书摘卡、长图**（R12 已做）对同人世界照常可用，但不自动带上作品名水印或宣传语，避免“借名宣传”（江南案的不正当竞争点）。
6. 公开发布前，许可证与免责声明一起定（[接手协议](../../AGENTS.md)第 1 节已要求公开前另定许可证）。

### 3.3 从几句话或一段粘贴导入世界

> 首版只做前两行（一句话、作品名加身份）；粘贴整理和卡片导入作为以后的候选。

| 输入 | 处理 | 产出 |
|---|---|---|
| 一句话（“灵气复苏的现代都市，我是刚觉醒的外卖员”） | 复用现有“AI 帮我补全”和“整理设定集”（`codex`）的思路，换成题材中性的提示词 | 故事设定、世界观卡、3～6 张势力/地点/设定卡、开场提示 |
| 作品名＋身份（“我穿成某部仙侠小说里的炮灰师姐”，作品名由玩家填） | 同上，另请模型把它记得的原著关键剧情写进世界卡或要点，并标明“AI 的记忆，可能不准” | 同上，原著剧情写在世界卡或要点里，可以编辑 |
| 粘贴一段百科式简介（数千字以内） | 分段整理：先抽世界观与力量体系→再抽人物（进人物表，来源标“原著”）→势力、地点→剧情节点；超长时提示“只取前 N 字”或分批 | 同上，人物直接进人物表（态度默认“一般”，与主角关系由玩家选的身份决定） |
| SillyTavern 角色卡 V2/V3（PNG/JSON）或独立 World Info JSON | 程序解析：`character_book.entries` / World Info 条目 → 设定集卡片（keys→别名，content→正文，comment/name→名称，constant→放进要点或世界观卡）；`description`/`scenario` → 故事设定；`first_mes` → 开场（自己写模式） | 不经 AI，导入后可在设定集里改 |

## 四、这种模式的开局引导

别人的做法：

- **题材入口**：MissAI 首页“八大题材”；刀锋大千世界按题材筛选；Dreamjourney 按 Explorer/Book 等标签；起点、番茄按分类。共同点是题材卡＋一句钩子＋热门程度。
- **万能开局**：Dreamjourney 的“Fantasy Isekai：故事由你决定”“Write Your Own Story”、AI Dungeon 的 Quick Start 都是最热门入口之一——很多玩家只想“随便穿一个”。
- **一句话生成**：AI Roguelite 一句话生成整个宇宙；猫箱一问一答的创作助手；Infinite Worlds 世界生成器自动给出 3～4 个主角和 3～5 个技能。
- **AI Dungeon 的 `${问题}` 占位符**：剧本在开局时只问几件事（名字、性别、职业），其余预填。

对我们：

- 现有“作者模式”开局（模板灵感＋一句话想法＋故事设定＋主角＋穿越方式＋开场）**原样保留**，只在最上面加一个模式切换和题材网格；不另起一套流程，避免两套界面。
- “随便穿”分两级：在题材网格里点“随便穿”＝随机题材＋随机模板＋随机身份；在某个题材里点“随便穿”＝这个题材内随机。
- “一句话想法”在异世界模式下的“AI 帮我补全”会同时起草世界卡（见 5.6）。

## 五、设计提案（精简版）

> 第二节的题材机制表，是“这些题材在网文里通常有什么”的调研记录，**不是要做的功能清单**。按用户意见，这些内容都放进世界卡的文字里，由玩家或 AI 来写。

### 5.1 异世界模式关掉的历史规则

| 历史模式的规则 | 在代码里的位置 | 异世界模式下 |
|---|---|---|
| 叙事者身份写死为“一部历史互动小说的作者兼叙事者” | `turn.ts` 中 `systemParts` 的第一行 | 改为“一部互动小说的作者兼叙事者” |
| 人物对白“带时代口吻”；称谓、货币、器物、制度要“符合那个时代” | `turn.ts` 的写作要求和没有时代卡时的兜底句 | 改为“符合这个世界和人物的身份”，并以世界卡为准 |
| 开场的记录块必须给出年号纪年 `date`（`era` / `year` / `ceYear`，中国背景用农历） | `turn.ts` 的 `OPENING_EXTRA` | **关闭**。只要求一句自由的时间说法（如“宗门纪元三千年 春”“末日第 37 天”），程序按“第 N 日”往后算。现有 `date = null` 的路径本来就支持【待验证界面上各处显示是否自然】 |
| 农历、干支、节气、年号表 | `calendar/date.ts`、`CalendarRules` | **关闭**（不设 `eras`，也不设 `lunar`） |
| 子丑寅卯的时辰说法 | `calendar/clock.ts` 的 `timeOfDay` | 按世界选择：古风世界保留时辰，其他世界用钟点或“清晨 / 午后 / 深夜”【需要一个小开关】 |
| 货币示例全是贯、文、两、denarius | `OPENING_EXTRA` 里的 `currency` 示例 | 换成中性示例（灵石、金币、信用点）；允许没有货币。货币规则本身不变 |
| 时代用词检查与提醒（“不要出现”清单、`taboos`、`watch`） | `era/taboo.ts`、`settings.tabooHints`、`upkeep.ts` | **默认关闭**。玩家可以在世界卡里写一行“这个世界没有的东西”，沿用同一套提醒，但不强制 |
| 内置时代卡组（唐天宝等），以及史料、物价、称谓资料 | `content/eras/` | 不使用。只有世界卡，可由 AI 整理，也可由玩家自己写 |
| 天下大事（卡组史事，固定 / 可变） | `timeline.ts`、`state.timeline` | 默认为空，界面上改叫“世界大事”。玩家可以自己加，也可以不用 |
| 改史记录：记录块 `deviation`，“这一世小传”里的“改史”段 | `turn.ts` 的 `RECORD_FIELDS`、`state/apply.ts`、`life.ts` | **关闭**。提示词不要求写 deviation，小传不显示“改史” |
| 过些日子的报告写“天下风声，符合时代” | `turn.ts` 中的 `skip` | 改为“外面的风声” |
| 整理设定集时生成的是“时代卡”，按“真实朝代就写真实情况”整理 | `codex.ts` | 改为整理“世界卡”：一句话世界、力量或规则、势力格局、钱与物价、日常风俗、文风；只补故事设定没写到的部分，不改玩家写的内容 |

**保留不变**（与题材无关的通用部分）：故事设定、要点、额外规则、设定集（人物、地点、势力、物品、设定卡）、行囊与钱、伤病状态、目标与心愿、时间推进与过些日子、章节摘要、相关旧事、运势（沿用 R11-T008 的三档，默认“只作参考”）、难度、内容尺度、视角、文风、重说、世界线、查一查、导出备份。

### 5.2 数据改动（尽量小）

所有新字段都可以缺省，缺省时就是历史模式，旧存档不需要迁移，也不新增表：

```ts
interface WorldSettings {
  // ...现有字段不变
  /** 缺省按 "history" 处理。 */
  mode?: "history" | "free";
  /** 只影响时刻怎么说；缺省时历史模式用时辰，异世界模式用钟点。 */
  clockStyle?: "时辰" | "钟点" | "时段";
}
```

- 世界卡就是现有的“时代”卡（`CardKind = "时代"`，每局至多一张，常驻），异世界模式下界面上显示为“世界”。不新增卡片种类。
- 主角现有的 `cheat` 字段（金手指，目前基本没有用到）在开局页露出来作为可选的一句话，有内容时放进【当前】。这对系统流、穿书、重生都有用，而且只是一行文字，不是机制。
- 开局可选的穿越方式在现有四种外加一种“穿进一本书或一部剧”，只影响开场提示词的写法。

### 5.3 提示词改动

以 `turn.ts` 现在的 `turn-14` 为基准，记为新版本，并按 PLAN_V3 §8.3 跑评测（事先登记费用上限）：

1. 按 5.1 改叙事者身份、口吻、兜底句、开场字段和货币示例，`mode === "free"` 时去掉 `deviation`。
2. 加一行世界一致性要求：“世界卡里写的力量、规则和限制要前后一致；主角不能凭空得到世界卡、金手指和【当前】里没有的能力。”这是为了防止玩家最常抱怨的“一句话就成神”，只是一句文字，不是机制。
3. 世界卡在上下文中放在原来时代卡的位置，长度限制沿用 `ERA_CARD_LIMIT`。
4. `codex.ts` 新增一个异世界版本（见 5.1 最后一行）。

### 5.4 唯一的可选机制：主角面板（默认关闭）

- **给玩家的好处**：喜欢修仙、异世界升级的玩家会反复问“我现在是什么境界、会哪些技能”。这件事要是只写在正文里，几十回合后容易被模型忘掉或改名，玩家也没有地方一眼看到。
- **做法**：不内置任何境界表或等级表。开启后，主角多出一块**自由文字**的“面板”（例如“境界：筑基中期；功法：某某诀（小成）”），由玩家或 AI 写。它每回合放进【当前】，AI 在记录块里用一句 `"panel":"更新后的面板"` 改写，改动像其他记账一样可以撤销。程序不解析其中的数字。
- 开关放在“本局设置 → 玩法”（和运势开关放在一起）。默认关闭；修仙、异世界模板也默认关闭，只在模板说明里提一句“可以打开主角面板”。
- 不做系统任务、点数、稀有度、副本、计量条、原著节点这些机制：系统任务用现有的支线目标就能记（期限和奖励写在目标的文字里），点数用货币记，原著剧情写在世界卡或要点里。等试玩反馈表明确实需要，再按“可选、默认关闭、写明好处”的原则逐个评估。

### 5.6 新开局流程

```
新的故事  [历史] [异世界]          ← 顶部切换，记住上次选择
异世界：
  模板卡片（10 个）＋ 随便穿 ＋ 自己写世界 ＋ 知名作品世界
  或“一句话想法” → [AI 帮我补全]：补故事设定、主角、开场提示，并起草世界卡
  → 进入现有的开局设定页；“更多设置”里多出“世界卡”预览，以及金手指、时刻说法两个可选项
  → 开始
```

导入 SillyTavern 卡片和世界书（见 3.3）不放进首版，作为以后的候选。

### 5.7 对照六条体验支柱

- **代入、流畅**：只多一个切换和一排模板，玩家可以一步不改直接开始。
- **掌控**：世界的规则完全由玩家写的文字决定，随时可在设定集里改。
- **记得住**：沿用现有的记忆、人物、物品和时间；需要时可以打开主角面板。
- **有盼头、有后果**：靠故事本身、目标和运势，与历史模式一样。
