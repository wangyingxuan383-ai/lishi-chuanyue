### D008 可恢复回合与原子提交

- 状态：已采纳；不等于功能已实现或已实测。
- 问题：断流、解析失败、重试和并发怎样避免破坏世界？
- 方案：请求带 operation_id 与 expected_head_turn_id；每分支单写。操作状态遵循 PLAN_V2 5.4，草稿在 validating 阶段通过校验后，在短 SQLite 事务中一起提交正文、选择、状态快照及 head，只有 committed 回合进入正式上下文。
- 理由：玩家看见的流式草稿不能在校验失败时偷偷变成事实；操作去重和 head 校验可防止重复提交与旧状态覆盖。
- 代价/限制：提交前必须限制下一轮行动；失败需清楚展示并支持安全重试。无法保证远程服务商不对断线请求计费。
- 复议条件：需要同分支多人或并发编辑时另行设计；不能以放松原子提交解决性能问题。
- 关联任务：M01-T004、M01-T007、M02-T004、M02-T005、M04-T002、M06-T004。

### D009 严格操作预算与独立摘要预算

- 状态：已采纳；不等于功能已实现或已实测。
- 问题：研究、提取、修复和重试是否会无限增加调用？
- 方案：同一操作内所有生成、提取、修复及研究模型 HTTP 请求合计最多两次；每次网络尝试均计数。搜索 HTTP 独立最多一次，结果最多五条。摘要是独立 operation，有预算且可延后。
- 理由：用户希望可控成本和兼容端点优先；显式预算避免隐藏的多 Agent 调用。
- 代价/限制：若一次模型研究已占额度，主调用后可能无修复额度；此时安全失败/延后，不发第三次请求。实际金额依赖可靠 usage 与配置单价。
- 复议条件：真实体验证明预算过紧或用户明确选择更高预算时复议；任何变更需记录调用上限与 UI 告知。

### D011 平台 SecretStore：DPAPI 与 Android Keystore

- 状态：已采纳；不等于功能已实现或已实测。
- 问题：如何持久化 API Key，同时不新增保险库口令？
- 方案：Windows 使用当前用户 DPAPI；Android 用小 Kotlin 插件调用 Keystore AES-GCM，密文保存在应用私有目录。通过窄接口供 Rust 保存/读取/删除，UI 不取得存储的明文。
- 理由：可使用平台提供的秘密保护能力；符合个人手机使用体验。与曾考虑的 Stronghold 口令路线相比，无需额外解锁口令。
- 代价/限制：需维护平台桥接；卸载、设备迁移或平台密钥失效后可能需要重新配置 Key；存档仍应可读。
- 复议条件：保存、读取、删除或恢复探针失败时停止功能扩张并修订；绝不静默切换明文或硬编码口令。

### D019 使用系统证书验证并显式初始化 Android TLS

- 状态：已采纳；源码与ARM64编译通过，Android HTTPS运行待验证。
- 问题：reqwest0.13的rustls默认平台验证器需要Android JVM支持，仅HTTP与APK构建会掩盖未初始化的证书验证问题。
- 方案：继续使用系统信任链，不关闭证书校验。Android壳固定verifier0.7.1/jni0.22.4，Gradle从Cargo.lock解析android shim0.2.0并引入匹配`org.rustls` AAR；保留ProGuard规则。Tauri/Wry JNI0.21回调内新建Application context引用，经窄范围raw桥初始化0.22，成功后才开放探针请求。
- 理由：系统信任链跟随平台更新；explicit ready检查避免异步初始化尚未完成时发送请求。网络核心仍不依赖Tauri/JNI初始化细节。
- 代价/限制：目前Tauri与验证器JNI版本不同，需要两处有安全说明的unsafe桥；上下文初始化及DEX类存在不证明HTTPS或错误证书拒绝已经运行通过。release/R8及设备配置还需验证。
- 复议条件：Tauri/Wry升级到同版JNI后移除桥；平台运行或证书拒绝失败时修正初始化，不以关闭验证或静默更换信任源规避。
- 关联任务：M01-T004、M01-T008、M02-T001；补充D005，不替代现有共享核心路线。
- 依据：[上游Android集成说明](https://github.com/rustls/rustls-platform-verifier#android)、[0.2.0官方POM](https://raw.githubusercontent.com/rustls/rustls-platform-verifier/maven-archive/android-release-support/maven/org/rustls/rustls-platform-verifier/0.2.0/rustls-platform-verifier-0.2.0.pom)、[JNI0.22 API](https://docs.rs/jni/0.22.4/jni/struct.EnvUnowned.html)，2026-10-12核实。上游README有旧坐标/API示例，实施按匹配版本源码与POM。
