## 入口、数据与预算

使用Windows实际原生核心及本机已配置模型。Key仅由SecretStore读取，不导出到脚本/日志，不修改用户旧世界。另建带“验收”标题的合成世界；该世界必要上下文会发送给用户配置的端点。记录模型、配置修订、提示词/协议版本，端点用标签或指纹关联，不在报告复制凭据。

先一次连接检查，401/403/429/503/超时等失败就停止后续真实请求，保留诊断，不自动重试。凭据或端点由用户修复后才开启一次新的明确评测。计划的基础运行上限为一次连接、30个主线回合、分支/快进/AI回顾各一个样本；每operation最多两次、当前实现实际只发一次。扩大到其他背景前先登记增量样本及预算，不暗中循环直到成功。

连续三十回合要求真实模型持续生成并成功提交，不能用演示补足或删掉失败记录。失败后不重发同operation；记录错误、正式head/state是否保持和实际HTTP次数，再判断问题需修实现、服务还是样本。暂停等待外部条件不算三十回合完成。

## 主线样本与检查

主线使用唐代普通人的公开背景，从寻找工作/谈报酬开始；始终以实际已发生状态续写。以下是情境目标，不能预先强迫模型认定尚未发生的结果。

| 回合范围 | 情境目标 | 检查方法 |
|---|---|---|
| 1～5 | 找工作、明确支付、购买物品、询问信息 | 从正式前后状态检查时间不倒退、收支可追溯、实体ID存在；正文中的金额/地点/物品需人工逐条核对 |
| 6～10 | 建立一个有名字的关系、约定或未解决事项 | 观察是否记录为关系/事件/持续状态，人物所知依据是否真实；未被告知的秘密不得自动出现在主角行动或他人对白 |
| 11～15 | 使用/转交已有物品、重访关系、负担或伤病 | 不能重新发明同一物品或无故清除债务/伤病；库存与叙事对应，未知信息保持未知 |
| 16～20 | 改称/回顾早期承诺、固定已有事实提醒 | 二字姓名/旧称召回及来源可见；固定提醒不能改事实，回顾从原文生成，旧对白裁剪不删除正式持续状态 |
| 21～25 | 让剧情自然推进、处理未解决线索 | 不替玩家接受重大条件；阶段变化需正式事件/状态记录，不仅写在正文；与历史基线冲突时说明玩家偏离或不确定 |
| 26～30 | 复查资金、物品、关系、约定和旧情境 | 对照实际早期提交记录；抽取至少五条关键事实，核对上下文trace包含正确可见事实，不能仅问模型“是否记得” |

每回合保留action、head前后、正式状态差异、角色可知DTO、输出或安全错误、CallAttempt/usage与人工审查结论。自动检查只判定可确定的协议和状态规则；正文因果、时代细节、角色自然性和重要选择是否被越过由人工审阅。无研究来源的具体史实标“未核实”，不能凭流畅文案给高准确率。

## 补充样本

- 分支：从一个已提交旧节点分叉，在新线上作不同选择。对比父线head/state不变，新线不继承分叉后新增的秘密、伤病、资产和资料。固定十线测试仍是硬隔离证据，真实样本评价叙事是否遵守这些输入。
- 快进：保存有限目标只登记，不推进；一次模型段遇关键选择必须先保存已发生事实并暂停，不在选择前生成后续结果。恢复需玩家真实提交决定并明确继续。单次没有触发关键决定要据实记录，不能伪称已验证暂停。
- AI回顾：选择已提交原文，检查摘要来源范围、关键事实和branch可见性，usage未知如实保留；回顾前后正式世界完全相同。
- 更广背景：原计划包含明代低级官员、清末城市居民、古罗马普通人、近现代平民和架空情境。登记独立开局及实际样本后再评价；没有跑过的背景写未执行，不由唐代样本推定其他时代质量。

## 通过与未通过

三十回合主线必须完整，代表样本有记录，无未解决硬事实冲突、跨线泄漏、无故扣款、自动替玩家决定或秘密泄漏。出现关键缺陷要保留失败、修复并针对性复测；普通文字偏好与事实缺陷分开。不编造模型随机文案的确定性测试，不把用户未反馈写成体验认可。

结论分为工程规则通过、真实模型样本通过、仍需历史核实和用户反馈待验收。真实Brave没有凭据时独立标未执行，不能将mock搜索返回当真实史料。没有单价或usage时费用未知，不据预留次数伪造账单。
