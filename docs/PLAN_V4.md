# AI 历史穿越模拟器 · 第四版总计划（v4 打磨与完善）

> 编写：2026-10-17（Asia/Shanghai）；同日按用户意见修订一次（见第 8 节）。起因：0.8.0 已经能玩、也找不出大毛病，但用户觉得“无论是精细度还是功能感觉，都不像是一个完善的作品”。
>
> 本计划是**总纲**：只划定要研究和优化的方向、先后顺序和工作方法，**不写具体方案**。每个方向先做深度调研，调研结论写成该方向的小计划，经检查后再动手。
>
> v3 计划（[PLAN_V3.md](PLAN_V3.md)）里的引擎、数据和架构设计继续有效；本计划管“从能用到好用、从功能齐到像成品”这一段。任务状态仍只记在[任务台账](TASKS.md)。

## 0. 这一版和 v3 有什么不同

- **视角变了**：v3 问“游戏缺什么功能”，v4 问“作为一个成熟的手机 App，玩家会期待什么”。很多方向和历史题材无关，是所有好 App 都有的东西：新手指引、帮助、反馈、动效、设置、无障碍等。
- **电脑端提上日程**：手机端已基本成形，电脑端从“能跑就行”改为同步跟进；之前定为不做或以后再说的内容（网页版、插图、语音、分享等）重新排进优先级。
- **两条腿走路**：这个 App 一半是游戏，一半是工具（连接 AI 服务、管理存档、设置）。第一稿只想了游戏那一半，用户随手就指出工具那一半的大量缺口（获取模型列表没人提示、自定义服务不能改名、服务设置过于简单）。修订后，工具那一半单列三个方向（J、K、L），并且第一档先做。
- **步子迈大**：用户希望尽快完善，可以在没有玩家反馈、没有真机测试的情况下先推进。凡是只有真机或玩家才能确认的结论都标【待验证】，等用户试玩后再校正。

## 1. 目标

1. **像成品**：第一次打开不迷路；每一步操作都有反馈；没有空白、生硬、像表单的页面；细节统一（间距、字号、文案、动效）。
2. **好上手**：玩家不看说明也能玩起来，想深入时有地方能学；各种高级功能找得到。
3. **用着顺手**：常用操作步骤少；手机上用手势、长按、滑动等自然交互；电脑上有键盘、鼠标、宽屏的便利。
4. **有完整感**：除了“玩下去”，还有回顾、收藏、分享、成就、图鉴这类让一局故事“有东西留下”的功能。
5. **有特色**：在成熟 App 的骨架上，保留并加强“宣纸书卷”和历史穿越的味道。

## 2. 研究与优化方向

分十二个方向：A～I 是游戏那一半，J～L 是工具那一半。每个方向只列**要回答的问题**，答案由调研和逐屏审查给出。这里列的问题只是起点，不是全部；每个方向调研时都要用第 4 节的“逐屏逐项检查”把问题补全。

### 方向 A：第一次使用与新手指引

- 第一次打开到读到第一段好故事，要走几步、花多久？成熟产品是多少？
- 还没有 AI 服务的玩家怎么办：连接服务这一步怎样讲清楚、怎样少出错？能不能先“试玩一段”再连接？
- 第一局怎么开：推荐、随便穿、模板、自己写，各适合谁？新手默认看到什么？
- 进入第一局后要不要引导（高亮提示、分步引导、示范回合）？引导什么、何时出现、怎样不烦人？
- 各种“第一次”（第一次重说、第一次快进、第一次打开角色面板）要不要就地提示？

### 方向 B：游玩指导与帮助

- 需要一份怎样的“游玩指南”：入口放哪，按什么组织（玩法、功能、技巧、常见问题）？
- 每个功能怎么就地说明（问号、长按说明、空状态里的提示）？
- 怎样教会玩家“写得好就玩得好”：示例行动、写法提示、好的开局示范？
- 出错时（连不上、被拒绝、没写完）的说明和下一步，怎样做到一看就懂？
- 有没有“这局玩到哪了”的帮助（回顾、前情提要、当前目标）？

### 方向 C：前端视觉与精细度

- 和成熟产品逐屏对比，差在哪：层次、留白、对齐、字号、颜色、边框、阴影、图标？
- 是否需要一套完整的图标、插画、装饰元素（印章、纹样、分隔线）？
- 各页面的空状态、加载状态、出错状态是否都设计过？
- 文案能否统一成一种口吻（玩家语言，带一点书卷气）？
- 三套主题、不同字号、窄屏和宽屏下是否都整齐？

### 方向 D：交互与手机手势

- 哪些常用操作步骤太多：继续、重说、换版本、改一个字、查看人物、记住一件事？
- 手机上还能用哪些自然交互：左右滑动换版本、下拉、长按菜单、双击、拖动、摇一摇、触感反馈、音效？
- 输入怎样更方便：快捷行动、常用语、语音输入、选中正文引用、输入框放大？
- 阅读怎样更舒服：翻页还是滚动、自动滚动、阅读进度、跳转、全屏沉浸？
- 返回键、手势返回、切到后台再回来，各种情况下行为是否符合直觉？

### 方向 E：电脑端同步

- 电脑上玩家期待什么：快捷键、右键菜单、悬停提示、拖拽、多窗口、更大的阅读区？
- 宽屏布局还能怎样利用：侧栏常驻人物与设定、目录、对照查看？
- Windows 安装与更新：安装包、开始菜单、桌面图标、自动更新？
- 手机和电脑之间怎样转移存档（文件、二维码、局域网）？
- 网页版（之前定为暂不做）现在值不值得做，做到什么程度？

### 方向 F：内容与开局体验

- 开局模板够不够、好不好：数量、朝代覆盖、身份多样性、封面与简介？
- “灵感”怎样呈现得像一个书架或剧本库，而不是按钮列表？
- 开局后的第一段，怎样稳定地好看（悬念、代入、清楚的处境）？
- 内置时代资料要不要扩充（更多朝代卡组）？

### 方向 G：完整感功能

- 一局故事怎样“留下东西”：回顾长卷、编年史、人物关系图、地图、结局与图鉴、成就？
- 分享：长图、卡片、导出成小说文本或电子书？
- 书架管理：封面、分类、搜索、排序、置顶、归档？
- 插图、配乐、朗读（之前不做）现在是否值得做，成本和风险是什么？
- 统计：游玩时长、回合数、走过的世界线、花了多少钱？

### 方向 H：可靠、性能与细节体验

- 启动速度、首字时间、长局滚动、切换页面是否流畅？
- 断网、服务出错、切到后台、来电、低电量等情况是否都有妥善表现？
- 数据安全感：自动备份提示、导出提醒、误删恢复（回收站）？
- 无障碍：字号放大、对比度、读屏、色弱、单手操作？

### 方向 I：历史穿越特色

- 成熟 App 的骨架之上，怎样让“历史感”贯穿：纪年、称谓、物价、天下大事、名人？
- 穿越者的优势与代价怎样更有体感（知道未来、现代知识、格格不入）？
- 运势与难度（用户 2026-10-17 反馈，见台账 R11-T008）：运势只作参考、不压过情理（一千人打二十人不该因“不顺”而败）；概率要调；玩法机制都应能在设置里开关。
- 有没有可以成为招牌的独特功能（如“史书记载 vs 你的世界线”对照）？

### 方向 J：AI 服务与模型管理

玩家第一个要过的关，也是用得最久的设置。成熟的 AI 客户端（Cherry Studio、Chatbox、LobeChat、SillyTavern 等）在这里做得很细，我们只有最简单的一版。

- 服务列表：自定义服务能否改名、加备注、排序、复制、停用？同一家能否配多个？怎样一眼看出哪个在用？
- 填写过程：填好 Key 是否自动获取模型列表？模型能否搜索、按用途分组、显示上下文长度和价格？手动填写的模型能否记住？地址写错（少了 /v1、多了斜杠、用了网页地址）能否自动识别并提示？
- Key：能否显示/隐藏、一键粘贴？能否查余额（有些服务商提供余额接口）？各家“去哪里申请 Key、价格多少”的入口？
- 模型分工：剧情、整理记录、查一查能否用不同模型？主服务出错时能否自动换备用服务？游玩中能否快速切换模型？
- 生成参数：温度、最长输出、推理强度、超时、重试这些要不要开放、放在哪、怎样不吓人？
- 测试与诊断：测试连接给出什么（耗时、模型回的一句话、出错原因与修法）？
- 费用：每个模型的价格、按服务和模型分的用量、预算提醒？
- 迁移：服务配置能否导出导入（不含 Key）、手机和电脑之间能否转移？
- 新手：从没听说过 API Key 的玩家怎样被一步步带着配好？

### 方向 K：设置与偏好

- 设置怎样分组（服务、阅读、游玩、数据、关于）？要不要搜索？每项有没有说明和预览？能否恢复默认？
- 阅读偏好（字号、行距、段距、字体、主题、翻页、常亮、动效）、游玩偏好（默认篇幅、选项数、视角、内容尺度的默认值）、提醒与声音、触感，是否齐全？
- 全局设置和“本局设置”的关系是否清楚（新开一局默认用什么、改了会不会影响已有的局）？

### 方向 L：App 基础与数据管理

所有成熟 App 都有、和游戏内容无关的部分。

- 关于页：版本、更新说明、开源许可、隐私说明、作者与反馈渠道。
- 更新：通过 GitHub 发布的安卓包和 Windows 程序，怎样检查新版本、看更新内容、引导覆盖安装？
- 反馈与诊断：出了问题怎样一键导出脱敏的诊断信息？
- 数据：存储占用、自动备份在哪里、保留几份、怎样恢复；误删的世界能否从回收站找回；手机和电脑之间怎样转移。
- 书架管理：世界能否改名、复制、置顶、归档、搜索、排序、加封面？
- 系统交互：确认对话框（现在用的是浏览器自带的确认框，不合风格）、可撤销的提示条、权限说明、返回键与手势。

### 方向 M：无限制穿越（异世界模式）

用户 2026-10-17 提出：既然做了穿越，再做一个不限于真实历史的模式——穿越到异世界：日式异世界、仙侠、奇幻、玄幻、武侠、科幻，或电视剧、电影、小说里的世界。比历史穿越更自由、机制更少。

- 和历史模式比，哪些机制要关掉（用词提醒、纪年与货币规则、天下大事年表、历史偏离），换成什么（如穿书时“原著剧情”与“你改变了什么”）？
- 不同题材需要哪些可选的机制模块（修为境界、等级技能、系统任务、门派势力），哪些只靠设定卡和提示词就够，哪些要程序记账？
- 开局怎么选：题材、世界模板、一句话让 AI 写出世界观；同人与原创世界怎样处理（不内置受版权保护的文字，玩家可以自己写或粘贴梗概）？
- 调研：`docs/research/FREE_MODE.md`。

### 方向 N：历史穿越的机制加深

用户 2026-10-17 认为历史模式的机制还不够完善。

- 身份与前途（科举、官职、经商）、家业与收支、人际与家族（婚姻、子嗣、师徒、仇怨）、名望分圈、技能与现代知识的代价、节令与灾年、穿越者被怀疑、历史偏离的连锁后果、结局与传承——哪些值得做，怎样让 AI 叙事和程序记账配合，不让界面臃肿？
- 运势只作参考、玩法机制可开关（台账 R11-T008）。
- 调研：`docs/research/HISTORY_MECHANICS.md`。

### 方向 O：功能广度

用户 2026-10-17 认为项目还可以增加很多功能。

- 同类产品和开源项目还有哪些功能（写作辅助、记忆与地图、多角色、配图与语音、剧情结构、分享、定制）？哪些适合单机、自带模型的我们，哪些要额外的接口（生图、语音、向量检索）并应做成可选？
- 调研：`docs/research/FEATURE_SURVEY.md`。

## 3. 轻重缓急

按“对完善感的提升”和“做起来的成本”排序，分四档。同一档内的方向可以并行。

| 档次 | 方向 | 理由 |
| --- | --- | --- |
| **第一档：先做** | J AI 服务与模型管理、K 设置与偏好、L App 基础与数据管理、A 第一次使用与新手指引、B 游玩指导与帮助、C 前端视觉与精细度、D 交互与手机手势 | 玩家最先碰到、最影响“像不像成品”；J、K、L 是用户已经指出的明显缺口；都不依赖新的 AI 能力，成本可控 |
| **第二档：紧随** | F 内容与开局体验、G 完整感功能（回顾、分享、书架、成就、统计）、E 电脑端同步（快捷键、右键菜单、安装包） | 决定玩家愿不愿意长期玩、会不会推荐给别人 |
| **第三档：评估后再定** | G 中的插图、配乐、朗读；E 中的网页版、存档互传；I 招牌特色功能 | 成本高或依赖外部服务，先调研可行性和价格，再决定做不做 |
| **第四档：持续进行** | H 可靠、性能与细节体验 | 每一档完成时都检查一遍，不单独排期 |

暂不考虑：多人联机、账户与云同步、应用商店上架（需要正式签名、隐私政策和资质，等用户决定公开发行再说）。

## 4. 怎样深度调研

每个方向都按同样的五步走，结果写进 `docs/research/` 和 `docs/validation/`。

1. **看现状，逐屏逐项检查**：在开发台按手机尺寸把相关页面完整走一遍，逐屏截图。除了凭感觉找问题，还要对**每个页面、每个列表、每个表单、每个输入项**过一遍下面的清单——第一稿漏掉的“自定义服务不能改名”“没提示可以获取模型列表”这类问题，靠清单才查得出来：
   - 名字：能不能命名、改名？重名时怎么区分？
   - 增删改：能不能新建、复制、修改、删除？删了能不能找回？
   - 排序与查找：多了以后能不能排序、搜索、筛选、置顶？
   - 默认值：第一次看到时填了什么？好不好？能不能恢复默认？
   - 输入：有没有格式检查？写错了怎么提示？能不能少打字（自动获取、选择、粘贴、记住上次）？
   - 引导：玩家怎么知道下一步该做什么？是靠设计（自动进行、按钮顺序、默认焦点）还是靠一行说明？优先靠设计，说明文字越少越好。
   - 状态：空的时候、加载中、出错时、完成后各显示什么？
   - 后悔：能不能撤销？危险操作有没有确认？确认框是否合风格？
   - 反馈：做完一件事有没有提示？提示能不能撤销？
   - 平台：返回键、键盘、电脑上的快捷键和右键菜单是否符合直觉？
   - 同类对照：成熟产品的同一个页面，有哪些我们没有的项目？
2. **看别人**：选 3～6 个成熟产品（AI 故事类、阅读类、国风文字游戏、普通的优秀手机 App），只看与本方向有关的部分，记录它们具体怎么做、玩家怎么评价，每条附来源和查阅日期。
3. **列差距**：把“我们现在”和“成熟产品”逐条对比，标出差距大小和影响。
4. **定方案**：从差距里挑出值得做的，写成该方向的小计划，说明做什么、不做什么、怎样算做好（验收标准），估算成本。
5. **做和验**：实现后重新截图对比、跑自动检查；只有真机或玩家才能确认的地方标【待验证】，列进下一次试玩问卷。

## 5. 计划书怎么写

文档分三层，各管一件事：

| 层次 | 文件 | 写什么 |
| --- | --- | --- |
| 总纲 | 本文件 `docs/PLAN_V4.md` | 方向、要回答的问题、轻重缓急、方法；不写具体方案 |
| 方向小计划 | `docs/plans/V4-A_新手指引.md` 等，每个方向一份 | 调研结论摘要、要做的改动清单、不做的和理由、验收标准、成本、要在真机确认的点 |
| 任务台账 | `docs/TASKS.md` 新增 `R11` 起的阶段 | 每个可单独验收的小步一条，和以前一样记状态、证据 |

方向小计划的固定结构：① 现状与问题（引用审查截图）② 别人怎么做（引用调研）③ 要做什么（按优先级）④ 不做什么 ⑤ 验收标准 ⑥ 待真机或玩家确认的点。

## 6. 阶段安排

| 阶段 | 内容 | 版本 |
| --- | --- | --- |
| R11 | 第一档：新手指引、游玩指南、视觉精细度、交互与手势 | 0.9 |
| R12 | 第二档：开局与内容、完整感功能、电脑端同步 | 0.10 |
| R13 | 第三档评估与选做：插图、配乐、朗读、网页版、存档互传、招牌特色 | 0.11 |
| R13b | 方向 M、N、O：异世界模式、历史机制加深、功能广度（先调研，再分批实现） | 0.10 起 |
| R14 | 整体打磨与发布：全局复查、性能与可靠性、试玩问卷、发布 1.0 | 1.0 |

每个阶段结束时：重新做一遍逐屏体验审查，与上一版截图对比；跑全部自动检查；打包可安装的版本；把需要真机或玩家确认的点汇总成试玩问卷。用户的真实试玩反馈随时插入，优先级高于本计划的排序。

## 7. 怎样判断“完善了”

- 第一次打开的新玩家，不看任何说明，5 分钟内能开局并玩完 3 回合，并且知道重说、角色面板、过些日子这几个功能在哪。
- 每个页面都有设计过的空状态、加载状态和出错状态；没有工程用语。
- 逐屏审查里的“高”严重度问题清零，“中”大部分解决。
- 和成熟产品对比的差距清单中，第一档、第二档的条目都有了结论（做了，或说明了为什么不做）。
- 电脑端有快捷键、右键菜单和安装包，能顺畅地玩完一局。
- 每个页面都按第 4 节的逐屏逐项清单检查过，查出的缺口都有了结论。
- AI 服务设置不看说明也能配好；常见的填错（地址、模型名）能被识别并给出修法。
- 用户试玩问卷中“像一个完整的作品”一项 ≥ 4（满分 5）【待用户试玩】。
