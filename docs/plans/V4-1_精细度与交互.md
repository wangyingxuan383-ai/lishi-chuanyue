# V4 第一档 · 小计划一：精细度与交互的硬伤（R11-T001～T004）

> 2026-10-17 · 依据：[逐屏审查](../validation/AUDIT_V4.md)、[国内调研](../research/UX_CN.md)、[海外调研](../research/UX_INTL.md)。总纲见 [PLAN_V4](../PLAN_V4.md) 方向 C、D、L（系统交互部分）。
>
> 这一份只收**审查里查出、调研里互相印证、不需要等用户拍板**的改动：都是“成熟 App 不会有”的硬伤。AI 服务设置（方向 J）、设置与关于页（K、L）等新调研出来后另写小计划；完整感功能（回目、分享、结语）属于第二档。

## 一、现状与问题

逐屏审查的总体结论是“读的体验接近成熟产品，操作的体验还停在工程师能用”。集中在五类：

1. **一眼可见的瑕疵**：启动页与空首页的印章读成“越穿”；没有地点时顶栏日期重复；吐司和吸附底栏压住内容；彩色 🎲 表情和印章风格冲突。
2. **点不准**：大量控件低于 44 像素（分段按钮 38、选项 42、重说 36、版本 ‹ › 只有 27 宽、页签 40、`summary` 18）；长按“重说”会穿透打开整段菜单。
3. **系统味**：9 处浏览器自带的 `confirm()` / `prompt()`；弹层没有关闭按钮，表单改了一半点到遮罩就丢；复选框是系统蓝。
4. **反馈不闭环**：中断时同一件事出现三处提示；失败没有“再试一次”；撤销后旧提示还在；撤销、重做没有任何反馈；首字前看不出在工作；模型卡住时没有“还在等”。
5. **藏得太深**：所有段落操作只能长按，游戏从没告诉玩家；输入模式要反复点才知道有几种，同一功能叫“导演 / 附加幕后要求 / 幕后”三个名字；首页最常用的“继续”反而最不显眼。

## 二、别人怎么做（摘要）

- 每个操作有退路、有反馈：撤销、回到这里之后给可撤回的提示条（海外 #8；Character.AI 的反面教训）。
- 出错说人话并给下一步按钮（海外 #12、国内 #5）。
- 危险操作和常用操作分开、二次确认、合风格（国内 #9、海外“抱怨汇总”）。
- 长按之外要有看得见的入口；第一次就地提示（海外 2.2 节）。
- 等待时有“写字”感（国内 #3）。

## 三、要做什么

### R11-T001 一眼可见的瑕疵

- 印章拆成两个竖叠的字，启动页印章不做淡入。
- 顶栏：没有地点时标题用世界名，副标题只放纪年时辰。
- 吐司：显示在顶栏下方，不压底部控件；页面跳转时清掉。
- 开局页吸附底栏加双线与渐隐，内容不被切掉。
- 运势标签的 🎲 换成单色的“签”字小印；标签字号 13。
- 复选框用朱砂色（`accent-color`）。
- 夜间主题灰掉的主按钮对比度修正；预览框圆角统一。

### R11-T002 点得准

- 全局最小点击区 44 像素：分段按钮、选项、回合工具（重说、‹ ›）、页签、`summary`、“改”这类小按钮；设计规范同步。
- 修长按穿透：按钮内的长按不再触发整段的长按菜单。
- 被长按的段落高亮，菜单顶部显示这段开头几个字。

### R11-T003 应用自己的对话框与弹层

- 新建统一的确认弹层和命名弹层（宣纸样式，危险操作按钮用朱砂描边），替换全部 `confirm()` / `prompt()`。
- 弹层右上角加关闭按钮；含表单的弹层有未保存修改时，点遮罩或返回先问“放弃修改？”。

### R11-T004 反馈闭环与可发现性

- 中断、失败只保留一个提示框，带按钮：续写 / 重说 / 再试一次；连续失败时多一个“去设置”。撤销、重做、换版本、回到这里时清掉旧提示。
- 撤销、重做、回到这里之后的提示条带“撤回”。
- 首字之前显示“落笔…”和朱砂光标；8 秒没有新字时提示“还在写，稍等…”。
- 第一次写完第三回合时，出一次性提示：长按段落可以改写、回到这里、记住这件事；段落末尾的工具行加一个看得见的“⋯”入口（只在最新一段）。
- 输入模式按钮点开是一个能看到全部四种的选择面板，统一叫“幕后”；附加幕后要求的输入框可以关掉。
- 首页：有存档时最近的世界做成大卡加“继续”，“开始新的故事”降为次按钮；卡片右上角加“⋯”菜单入口；卡片加朝代小印。

## 四、不做什么（这一份）

- 统一的 SVG 图标库：等新调研和设置页一起做（避免两次改动），先保证字符图标点击区够大。
- 结局卡、回目目录、分享长图、前情提要：第二档，另写小计划。
- 开局页两步化：和“第一次使用”一起做（方向 A 的小计划）。
- 角色面板人物小传、数值档位编辑：随方向 C 的第二批。

## 五、验收标准

- 逐屏审查第三节前 20 条中的第 1、3、4、5、6、8、11、14、15、16 条（以及对应的逐屏条目）解决，并在手机尺寸重新截图对比。
- 全项目不再出现 `confirm(` / `prompt(` 调用。
- 自动检查：单元测试、手机尺寸流程、桌面检查全部通过；手机尺寸流程新增：确认弹层取消与确认、失败后“再试一次”、撤销后的撤回提示、第一次长按提示只出现一次。
- 用脚本量出可点击元素的尺寸，低于 44 像素的只允许正文内的行内链接。

## 六、待真机或玩家确认

- 44 像素在小米手机上的观感、单手可达性。
- 长按高亮与触感反馈是否清楚。
- 吐司放在顶部是否容易被注意到。
