## 1. 产品意图与成功标准

### 1.1 项目定义

一个以历史穿越为背景、以自由行动和 AI 叙事为中心，通过本地结构化状态、长期记忆、世界线分支和按需历史研究，支持单人长期游玩的模拟器。

AI 提出情节、人物行为和状态变化；核心程序负责验证已定义的规则、提交正式世界状态、隔离世界线并恢复中断。完整的社会、经济和战争因果仍不可能由初期程序独立裁决，应如实说明模型推演与资料覆盖的边界。

主要开发者与初期主要使用者是项目发起人。软件成熟后发布到 GitHub，兼顾其他玩家安装使用。初期按个人项目可维护的复杂度建设，不提前引入账户系统、收费后台和社区运营平台。

### 1.3 成功标准分三层

1. **数据正确**：已提交状态、原始剧情和分支归属重启后保持一致；没有半回合结算或重复结算。
2. **信息可召回**：数百回合后，持续伤病、债务、物品、承诺和人物关系仍能在相关行动中进入上下文。
3. **叙事可玩**：自由行动获得有效回应，角色不会明显全知，快进有事件和选择，史实与已改变历史之间保持可解释关系。

数据库及召回可以用固定数据测试；叙事质量和模型对硬事实的遵守通过真实模型评测及试玩验收。不能把前两层通过写成“AI 永远不会犯错”。

## 2. 版本边界与产品默认值

### 2.1 首期平台与交付方式

- 产品主平台：Android ARM64，手机布局优先。
- 开发与辅助使用平台：Windows 11，提供共用核心的可玩版本。
- Android 在 M01 就进行安装、存储、网络、密钥、文件和进程恢复验证，每个可玩里程碑保留手机检查。

- 本地浏览器模式安排在核心版本稳定后，通过 localhost 服务调用相同核心，不依赖网页直接调用 Tauri。
- Android 最低系统版本、WebView 版本与测试设备型号在 M01 核实记录，尚未核实前不声称已兼容所有 Android 版本。

### 2.3 后续扩展顺序

厂商原生接口与更好的能力探测 → 历史数据源适配 → 更好的检索、关系和时间工具 → 专门经营、战争模块 → 地图、图片、语音等表现能力。云同步、多人和可执行插件需要单独的权限、服务与兼容设计，不纳入 v0.1。

### 2.4 默认策略

单人、文字、本地存档、BYOK、无需账户。默认动态历史、重要问题按需研究、关键决策暂停。中文是第一语言，界面使用国际化键。每个操作最多两次模型请求，最多一次独立搜索并采用不超过五条结果；摘要使用独立任务与预算。不自动跨服务商切换。未知使用量与价格显示为未知或估计。

公开许可证在 M07 首次公开前确定。当前不把第三方网页、数据库或字体视为可以随主程序再分发。

## 3. 玩家流程与界面行为

### 3.1 第一次使用

1. 进入欢迎和存档列表，离线也能打开已有剧情与状态。
2. 设置兼容 AI 接口地址、Key 与模型，用户主动点击连接测试。
3. 选择随机穿越或自定义开局；随机的实际结果在确认开局时可查看。
4. 核心验证开局配置，生成并提交初始世界和第一段叙事。
5. 玩家自由输入或选择行动，流式阅读，提交完成后进入下一回合。

连接测试属于单独操作，计入调用记录，不在进入设置页时偷偷发付费请求。缺少 Key 时仍可查看和管理本地存档。

### 3.2 开局配置

快速路径暴露背景地区、时代或随机范围、穿越方式、身份偏好、历史模式、叙事长度，其余采用模板默认值。详细路径增加姓名、年龄、语言、现代知识、初始物资、关系、能力、风格和自定义规则。

世界背景模板与人物模板逻辑分离。模板的实际随机结果在世界创建后固定保存；再次使用模板创建新世界，不复用上次游戏状态。

初期支持动态历史和自定义架空规则。更严格的史实锚点约束在资料完整度足够时增加，不以一个“严格”开关承诺全部重大历史事件必然被正确还原。

开局生成也遵守原子提交。用户看到但尚未提交的开场不是正式世界；失败时保留创建配置，允许重试。

### 3.3 操作语义表

| 操作 | 写入游戏状态 | 时间推进 | 处理方式 |
|---|---|---|---|
| 自由行动/点击选项 | 验证后写入 | 由结果确定 | 提交正式回合 |
| 继续剧情 | 验证后写入 | 由结果确定 | 行动种类为 continue |
| 更多选项 | 不写世界事实 | 不推进 | 独立建议操作，结果关联基准节点 |
| 世界外指令/OOC | 写叙事配置 | 不推进 | 单独输入模式；不作为主角言行 |
| 研究 | 写来源与研究记录 | 不推进 | 独立研究操作，不覆盖世界事实 |
| 固定提醒 | 写提醒记录 | 不推进 | 引用已有事实；不能使死者自动复活 |
| 修正世界事实 | 在新分支写入 | 不凭空倒退 | 明确修正操作、原因和变更记录 |
| 重写已提交回合 | 新分支提交替代回合 | 根据新结果 | 从原回合父节点重新行动 |
| 回溯/分叉 | 新分支 | 分叉时不推进 | 从已提交回合快照建立新节点 |
| 快进 | 分阶段写入 | 不超过目标 | 目标或关键决策边界暂停 |
| 归档/回收站 | 分支元信息 | 不推进 | 可恢复，保留后代所依赖的祖先记录 |

候选选项是建议，不是硬编码的唯一分支。自由输入不匹配选项时也必须正常处理。不能在模型生成中又提交第二个世界行动；输入内容可继续编辑为下一轮草稿。

### 3.4 Android 界面

主页面以正文、时间地点和输入为中心。候选选项可收起，输入框适配中文输入法。人物、资产、线索、时间线、分支、资料和设置通过抽屉或独立页面进入。

每个回合区分生成中、待验证、已保存和失败。普通用户只需要知道本轮是否已保存、能否继续、失败后如何处理；详细状态和调用原因在展开区域展示。

世界百科显示当前分支可见的人物、组织、地点、资产、关系与事件。默认玩家视角仅展示主角已知信息；高级检查界面可展示世界事实，但不得因此让下一轮 NPC 自动获得秘密。

### 3.5 Windows 与网页布局

Windows 在叙事旁增加可收起的状态和分支区域，复用全部核心行为。网页模式同样适配手机宽度，但首先作为本机浏览器入口。M07 不默认向局域网或公网开放服务；手机主要使用原生 APK。

## 4. 技术架构与模块边界

### 4.1 技术组合

前端 React + TypeScript + Vite；原生壳 Tauri 2；核心 Rust；数据库 rusqlite + bundled SQLite；异步与 HTTP 使用 Tokio/reqwest，TLS 使用可跨平台验证的 rustls 路线；JSON 协议使用 serde；所有具体依赖版本在 M01 构建通过后锁定。

Tauri 与插件的框架支持不等于本项目已兼容。SQLite、流式请求、密钥、文件 URI 和进程恢复必须在 Android 技术验证中通过。

### 4.2 最小代码组织

未来代码在仓库根组织为：共用前端、原生壳、独立核心三个主要包。核心最初使用一个 crate 内模块组织 application、domain、storage、provider、memory、research；secret 与 file I/O 由平台适配器实现。M07 再增加独立 local-server 包。

不在 M00 提前创建空代码目录或假接口实现。未来需要的 prompts、migrations、fixtures、evals 在对应任务中建立，并纳入版本管理。

### 4.3 调用方向

```text
React UI
  -> PlatformClient（Tauri IPC；后续 HTTP/SSE）
    -> Rust Application Service
      -> Domain / State Validation
      -> Context Compiler / Memory Retrieval
      -> ModelProvider / ResearchProvider
      -> Storage / Migration / Backup
      -> SecretStore / FileAccess 平台适配
```

核心不依赖 React、Tauri command 或浏览器环境。前端不执行 SQL、不读取密钥文件、不直接调用 Provider。业务测试可使用固定模拟 Provider 和临时数据库脱离 UI 运行。

原生流式更新由 Tauri Channel 传给前端。普通事件仅承担低频通知，避免高吞吐文本依赖无序广播。

### 4.4 核心应用接口

| 接口能力 | 输入重点 | 输出与约束 |
|---|---|---|
| create_world | 创建操作 ID、模板结果、配置 | 原子建立初始世界和主分支 |
| list_worlds/get_world | 世界 ID | 元信息及指定分支正式状态 |
| submit_turn | TurnRequest、expected_head | operation ID；流式事件与正式结果 |
| get_operation/cancel_operation | 操作 ID | 当前状态；取消不能撤销已提交回合 |
| list_turns/get_turn | 分支、分页或回合 ID | 仅当前可见范围 |
| fork_branch/rewrite_turn | 基准正式回合、名称或新行动 | 新分支 ID，原分支保留 |
| archive/restore/trash_branch | 分支 ID | 可恢复元信息，不删除祖先依赖 |
| update_director_settings | 分支、基准节点、配置变化 | 分支配置修订 |
| pin_memory/unpin_memory | 分支、事实或回合引用 | 版本化提醒记录 |
| research | 查询、相关年代与实体 | 来源、结论、争议，不推进时间 |
| save_provider/test_provider | 配置、密钥写入或测试操作 | 配置状态；不返回已保存 Key |
| export_world/import_world | 世界 ID、平台文件句柄 | 一致包或新导入世界 |
| diagnostics | 操作或世界 ID、范围 | 脱敏、由用户选择导出 |

调用接口是传输无关的 application service。Tauri command 和后续 HTTP route 只进行参数转换、身份/来源检查和事件传递，不再各自实现一次业务规则。

### 4.5 错误分类

对核心错误使用稳定的类别：配置缺失、验证失败、基准节点过期、已有操作进行中、网络失败、限流、请求拒绝、输出截断、协议不兼容、存储失败、导入不兼容、取消与进程中断。

前端展示可理解的恢复动作；详细诊断保留经过脱敏的错误类别、阶段、Provider 和操作 ID。禁止将 HTTP Authorization、Key、全部环境变量或服务器返回的秘密原样显示。

## 5. 回合协议、状态机与确定性规则

### 5.1 TurnRequest 的最小字段

| 字段 | 含义与约束 |
|---|---|
| protocol_version | 整数，首期为 1；不支持的版本直接拒绝 |
| operation_id | 客户端为一次意图生成的唯一 ID；查询和重发沿用，明确重新生成使用新的 ID |
| world_id / branch_id | 当前世界与分支；必须一致且处于可操作状态 |
| expected_head_turn_id | 请求基于的正式节点，初始分支可为 null；提交前再次核验 |
| action_kind | action、continue、fast_forward；研究、OOC 与选项刷新使用独立操作接口 |
| action_text | 玩家本次行动或快进方针；纯空白 action 拒绝 |
| fast_forward_target | 仅 fast_forward 使用，表示目标时间和关注项；必须晚于当前时间 |

所有 ID 使用与显示名称无关的稳定 ID。同名人物不会共用一个实体 ID。operation_id 的幂等性只适用于本地写入，不承诺外部服务商恰好收费一次。

### 5.2 模型输出约定

以下为协议规格示例，尚未建立运行时 schema 文件。实现时从 Rust 类型生成或校验共用前端类型，避免手工维护两套含义不同的协议。

```json
{
  "protocol_version": 1,
  "narrative": "已经发生的场景及结果",
  "choices": [{"id": "choice_1", "text": "下一步行动建议"}],
  "time_advance": {"elapsed_seconds": 3600, "display_text": "当日下午"},
  "state_changes": [],
  "events": [],
  "source_references": [],
  "uncertainties": [],
  "decision_boundary": null
}
```

`decision_boundary` 仅快进遇关键选择时使用，包含需要玩家决定的问题和候选行动。系统不能接受“先生成后续十年结果，再返回中途一个选择”。

正文、选项和状态变化必须能组成同一回合。纯聊天、不支持结构化输出的端点使用“正文生成 + 一次提取”路线；提取以正文和基准状态为依据，不能重新创造正文里没有发生的重大行为。

JSON 路线允许去除完整包裹输出的代码围栏及首尾空白，不使用任意截取第一个大括号到最后一个大括号的方式掩盖非法输出。未知操作、版本不符、关键字段缺失、实体引用无效均不能提交。

模型返回的来源引用只允许引用本次上下文已经提供的来源 ID 或已有研究记录；模型自行生成的 URL 仅为待查线索，不能伪装成已访问证据。

### 5.3 状态变化的允许类型

| 操作类型 | 必要语义 | 硬校验重点 |
|---|---|---|
| create_entity | 类型、名称、别名、初始属性 | ID 唯一；身份归属当前世界；引用合法 |
| set_entity_attribute | 实体、明确属性、旧值条件与新值 | 类型合法；不能绕过生死与时间规则 |
| change_resource | 所有者、资源与单位、增减数、原因 | 精确数量；单位匹配；不默许负库存 |
| change_relationship | 两个实体、关系类型与变更 | 两端存在；不依靠名称猜测 ID |
| add_or_resolve_condition | 伤病、债务、承诺等持续状态 | 有来源事件；解决状态不删除旧记录 |
| add_event / resolve_thread | 事件、相关实体、时间范围 | 不超过回合终止时间；因果引用已存在 |
| record_knowledge | 认知主体、事实引用、获知方式 | 事实与主体存在；不是给所有 NPC 自动复制 |

时间推进单独由 time_advance 表达，不同时接受 state_changes 中另一次隐式时间变更。核心内部的实际时间与显示文字关系由程序生成或核验，模型不能只改“显示年份”而不改时间。

数量以明确单位和精确十进制或定点值保存，避免浮点误差。债务作为负担状态或专门资源保存，不以“允许全部库存变负数”实现。首期不自动兑换不同货币或历史度量衡。

自定义世界规则可以声明特殊能力，但不能运行脚本。默认普通历史规则下，已死亡角色不能直接恢复为存活；玩家明确修正规则或事实时建立新分支并留痕。

### 5.4 请求尝试与正式回合分开

一个操作可包含至多两次模型请求，每次保存用途、阶段、状态、耗时、Provider 配置版本、提示词版本和 usage。失败输出作为草稿或诊断保存，不混入 committed_turns。

允许的状态与启动恢复行为：

| 操作状态 | 是否可进入下一正式回合 | 重启后的处理 |
|---|---|---|
| pending | 否 | 保留行动，标记中断或由用户明确重试 |
| generating | 否 | 标记 interrupted，不恢复不受控的网络线程 |
| validating | 否 | 可重新验证完整已保存输出；不隐式增加模型调用 |
| committed | 是 | 读取正式结果；重复查询返回同一结果 |
| failed | 否 | 展示原因，提供修复或重新生成 |
| cancelled | 否 | 保留输入；下一次提交须使用明确的新操作 |
| interrupted | 否 | 显示最后正式节点，允许用户重试 |

每个分支的操作串行化。运行时锁防止界面双击并发；数据库条件更新和唯一约束防止其他窗口或重启后的重复提交。分支 head 只在短提交事务内改变。

### 5.5 原子提交流程

1. 检查世界、分支、配置、调用预算和 expected_head。
2. 保存操作与玩家输入；从正式快照编译上下文。
3. 请求模型，边读流边发送已解码的 narrative 片段。它们始终是待提交内容。
4. 保存完整输出或失败原因，解析协议，验证状态操作，得到新的候选状态。
5. 如需一次提取或修复，先检查本操作剩余请求数，且修复不能绕过硬规则。
6. 开始短数据库事务：再次核验 head，写正式回合、事件、状态快照、来源采用关系及 operation 状态，再更新分支 head。
7. 提交成功后发布 committed 事件；失败回滚，正式世界仍停在旧节点。

计算候选状态和外部 API 请求不占用写事务。已提交之后才取消的请求返回正式结果，不能自动倒扣状态。提交前若已取消，事务不得继续提交。

### 5.6 流式消息

传给 UI 的事件统一包含 operation_id、单调 sequence 和事件类型：started、narrative_delta、stage_changed、committed、failed、cancelled。流片段必须正确处理跨 UTF-8 字符、SSE 多行、结束标记和截断。

JSON 流只展示已可靠解码的 narrative 字段，不将原始 JSON、机器状态或推理内容全部滚入正文。结构化流展示困难时可以暂时显示生成进度并在正文可解析后展示，不能因追求逐字效果破坏协议。

UI 重挂载时查询 operation 和当前 head；不根据内存里收到的最后一条 delta 猜测世界是否提交。完整草稿至少在生成结束时保存；进程被杀可能丢失尾部草稿，但不能丢失已提交回合。

### 5.7 无法完全自动判定的情况

结构合法、硬规则通过仍可能包含叙事矛盾，例如正文写“付了十两”而状态仅扣一两。初期保留状态详情、修正入口及固定情境评测；重大数值结果尽量在正文由正式结算值生成展示。

不增加每回合默认额外的“反思模型”。发现明确矛盾时本操作最多用一次修复，仍失败则不提交或明确请玩家选择修正方案。实际模型违反事实的情况进入 eval 记录，不以“程序裁判”措辞隐藏。

## 6. 数据模型、时间与世界线

### 6.1 存储布局与数据权威

每个世界一个 SQLite 文件，存于应用数据目录而非源码目录。世界库包含该世界全部分支、正式回合和派生记忆。存档列表读取世界元信息，辅助列表缓存可以重建，不另造一份权威世界状态。

API Key 与签名材料保存在独立平台 SecretStore 或外部安全位置。用户的真实存档不进 Git。模板配置可以导出，但不包含服务商秘密。

权威内容为：初始配置、不可变正式回合、正式状态快照、事件和明确配置修订。摘要、文本索引、百科展示缓存是派生内容，可重建，不能反向覆盖正式事实。

### 6.2 数据对象与关系

| 对象 | 核心内容 | 版本/分支关系 |
|---|---|---|
| world_metadata | ID、创建配置、格式版本、主角 ID、创建时间 | 世界级 |
| branches | ID、父分支、分叉回合、head、名称、归档/回收站状态 | 单父；分叉基准不可变 |
| committed_turns | ID、分支、父回合、行动、正文、选项、时间、协议与 prompt 版本 | 只追加，不改写旧正文 |
| operations/model_calls | 意图、基准 head、尝试、用途、状态、usage | 不是正式剧情 |
| state_snapshots | 对应回合与正式状态 JSON、版本、校验 | 每正式回合一个；不复制全文历史 |
| events | 时间范围、参与实体、因果引用、结果 | 关联正式源回合 |
| entities/relations/resources/conditions | 正式快照中的有类型对象及查询投影 | 投影可重建，不能成为第二事实源 |
| knowledge | 主体、事实 ID、获知事件或方式、确信程度 | 人物认知与客观事实分开 |
| summaries | 来源回合范围、摘要、模型与 prompt 版本 | 范围必须完全位于可见祖先路径 |
| pinned_memories | 已有事实或原回合引用、备注、启用修订 | 分叉时继承当时有效配置 |
| research_sources/claims | URL、摘录、时间范围、查阅日期、结论状态 | 来源可共享，采用关系属于具体回合 |
| bookmarks/config_revisions | 书签、导演配置、模板与偏好修订 | 支持按分叉节点恢复配置 |

物理表拆分由相应任务实现，上表固定语义与权威边界。不要为了列表展示给每个概念都提前建复杂关系模型。正式状态快照与查询投影必须在同一事务维护，投影发现损坏时由快照重建。

### 6.3 世界事实与人物认知

至少支持事实的公开性、主角已知、活跃 NPC 已知和秘密。人物相信的传闻可以指向一个与客观事实不同的 claim，并注明来源和状态。

叙事者可以知道用于推演的隐藏事实，但 NPC 对话上下文只能获得该角色或其群体已知内容。玩家打开调试视图不等于主角获得信息。

初期不为全世界每个 NPC 持续生成完整思想档案。只维护玩家相关人物、在场人物和影响当前事件的知识，其他角色按接触时建立必要记录。

### 6.4 时间模型

时间分为三类：

1. 系统现实时间：用于创建、调用、备份与开发记录，使用明确时区或 UTC。
2. 游戏推进时间：可比较的内部游戏日期/序数和累计推进量，不依赖 Unix 时间能够覆盖的年代范围。
3. 历史资料时间：原纪年文字、calendar、precision、earliest/latest 可选区间。

首期游戏内部采用可比较的公元纪年日期表示，内部纪年约定与公元前转换由一个统一时间模块承担；显示避免错误的“公元 0 年”。模糊史料日期不伪装成精确到某日，转换依据不确定时保留原文与范围。

出生日期精确时由当前游戏时间计算年龄；只有约年龄或出生范围时显示约数/范围。模型不能同时随意改年龄和生日。永久伤病、欠债和承诺在时间推进中继续存在，只有明确恢复、偿还或解决事件才改变。

快进不会用一次巨大年龄数字更新替代完整状态演变；结果至少交代相关人物、资产、关系与线索的阶段变化。无关社会细节可省略。

### 6.5 分叉和可见性算法

只允许从已提交节点分叉。新分支记录 parent_branch_id 和 fork_turn_id，初始 head 指向该节点，并读取其状态快照与当时有效配置。

检索可见路径从当前 head 沿正式父回合链回溯到世界初始节点。只有这条路径上的回合、事件及其有效修订属于该分支上下文。不能用“branch_id 相同或 parent_branch_id 相同”的宽查询替代祖先路径约束。

旧分支分叉点之后的摘要即使只多覆盖一回合也不能整段继承；需要裁掉范围或从可见原回合重新生成。同名人物和历史来源相同不能成为跨分支记忆共享的理由。

重写第 N 回合从其父节点创建新分支，使用原行动或玩家修改后的行动重新生成。主分支正文永不因此被覆盖。原有快照和记录保留，可回到旧结局。

归档隐藏分支但不影响祖先引用；回收站可恢复。首期不提供需要递归清理祖先依赖的永久分支删除或合并，后续设计后再开放。整个世界永久删除需要独立数据管理任务与恢复策略。

### 6.6 快照规模与优化门槛

初期每正式回合完整保存结构化状态，降低恢复与分叉复杂度。快照不包含全部历史全文、网页、摘要和日志；这些对象通过 ID 引用。

在 300 回合与多分支数据上测量体积、读取、写入与启动性能。只有实际规模成为问题后，增加周期检查点、增量状态或压缩；修改存储策略必须保留现有存档兼容和一致性测试。初期不搭建通用事件溯源平台。

## 7. 长期记忆与上下文编译

### 7.1 记忆层的职责

| 层 | 保存内容 | 召回方式 |
|---|---|---|
| 当前状态 | 日期、地点、主角、资源、持续状态 | 每次直接读取正式快照 |
| 当前实体 | 在场人物、相关组织、角色已知信息 | 实体 ID、地点、参与关系过滤 |
| 固定提醒 | 玩家要求持续关注的已有事实 | 有效修订和源事实校验 |
| 事件与线索 | 结仇、承诺、钥匙、债务、未解决事项 | 实体关联、状态、时间与重要性 |
| 相关原文 | 重要对白与行动细节 | 分支可见过滤后文本检索 |
| 章节摘要 | 旧阶段剧情梗概 | 源范围可见、与当前任务相关 |
| 历史证据 | 查证结论和来源 | 实体、年代、地区与问题匹配 |
| 最近对话 | 近期正式完整回合 | 倒序取样并控制预算 |

固定提醒不赋予事实修改权。例如“记住张某没死”与当前正式死亡状态冲突时，提示玩家采用事实修正分支；不能靠提醒优先级偷偷覆盖死亡事实。

### 7.2 召回顺序与中文检索

先提取用户行动中的实体别名与当前活跃实体，再读取相关关系、伤病、资源、承诺和事件，最后补充文本相关内容。按当前分支可见范围过滤后才能排序和返回。

中文初期采用稳定实体别名匹配、标签和 FTS5 文本检索结合。二字人名、昵称、同名异人、改名、地名和无空格长句都要有真实样例。短查询允许在已经按实体/时间/分支缩小的范围内使用受限子串搜索，避免整库扫描替代检索设计。

不在默认路线引入 embedding、向量库或 reranker。实际评测发现语义召回不足时，再记录新增服务、成本、索引版本和跨分支隔离设计。

### 7.3 Token 预算

每次请求记录端点声明或用户配置的 context_limit、输出预留、输入估计和实际 usage。端点能力未知时采用保守配置并标明估计，不能将模型名猜出的长度作为确定事实。

组装优先级：系统规则和协议、当前行动、主角/时间/关键持续状态、当前角色知识、固定提醒、相关事件、证据、摘要、最近对白。空间不足先去重和缩减低相关内容，不删除关键事实去塞更多小说原文。

必要事实和玩家行动仍超预算时停止请求，说明需减少输入或调整模型配置。不得静默截断行动、发送超过端点上限的请求或把溢出错误当随机失败无限重试。

### 7.4 摘要生成与重建

达到上下文或章节阈值后生成摘要，作为独立 operation 记录费用和源范围。生成依据优先使用原始回合、已提交事件与状态差异，避免不断把旧摘要再压缩导致事实漂移。

摘要记录世界/分支、起止源回合、prompt 版本、Provider/模型、生成时间及相关事件。失败不影响正式回合，可延后，旧正文仍保留。新摘要验证通过后替代其有效版本，不删除旧源记录。

分支发生后只采用完全位于其可见路径的摘要。提示词升级引起摘要重建可批量计划，但必须显式受预算限制，不在打开存档时触发海量调用。

### 7.5 固定长局验收脚本

至少构造 300 回合固定数据：第 5 回合受伤，第 30 回合结仇，第 70 回合得到钥匙，第 100 回合欠债，第 150 回合再次见仇人，第 300 回合进入需要钥匙的门。

分别验证正式数据库事实、召回结果是否进入上下文、真实模型是否遵守。不能只验证“数据库里有伤病字段”就认定长记忆体验通过。主角长期资产、婚姻、改名和多人同名追加进入情境集。

## 8. AI 适配、研究与成本

### 8.1 首批兼容接口

首批使用常见 Chat Completions 兼容协议，ProviderProfile 包含配置 ID、协议类型、base_url、model、secret_ref、超时、流式偏好、输出路线和预算。地址规范在适配层完成，不从其他业务模块各自拼接 /v1 或 /chat/completions。

Key 保存后以 secret_ref 引用；profile 导出不带认证字段。自定义请求头仅放高级配置，认证类值按秘密保存与脱敏。自定义模型名不要求存在于在线模型列表。

允许用户明确配置局域网或本地模型地址；外部研究网页不得改变 Provider 地址、认证头或模型配置。端点切换通过配置修订记录，已有剧情和状态不重写。

### 8.2 能力与生成路线

能力属于端点 + 协议 + 模型 + 配置组合，包含 streaming、structured_output、usage、context_limit 等。记录 unknown/supported/unsupported，以及信息来自声明、用户配置还是测试。

JSON 路线：一次主调用生成正文和状态；解析或验证失败时最多一次修复。TEXT_EXTRACT 路线：主调用输出正文，第二次提取状态，两次仍不可靠则失败。支持服务商 schema 时也必须做应用校验。

摘要、导演规划和研究是逻辑职责，不默认对应六个模型或六次请求。简单配置共用一个模型；高级配置将任务映射到其他模型时依旧受同一操作预算约束。

不保存服务商隐藏推理内容。调用日志保存必要的公开输入、输出和统计，并提供保存范围控制；真实游戏文本仍属于用户数据，不默认上传诊断。

### 8.3 提示词版本化

提示词模块包含核心规则、世界与历史约束、风格、角色知识、记忆、证据、最近回合、玩家行动和输出约定。提示词是仓库资产，记录版本或提交标识。

每次操作记录编译所用版本及上下文选择清单，便于解释遗漏来自状态、检索、预算还是模型。不在源码维护一个不断追加全部对话的超级字符串。

提示词或协议变更运行相关 eval；回滚版本影响新请求，不静默改写旧剧情。外部网页和用户导入资料以明确数据区域进入提示，不获得系统指令权限。

### 8.4 历史研究的数据流

```text
玩家研究问题 / 关键事实触发
  -> 查找已有来源与结论，核对年代、地区
  -> 必要时 ResearchProvider.search
  -> 保存标题、URL、摘录、查阅日期
  -> 形成有依据/推断/争议/未知结论
  -> 在主调用上下文中提供相关证据
  -> 保存本回合实际采用来源的关联
```

初期按规则、实体类型、玩家指定和缺少资料来触发，不增加默认额外模型专门判断每句话是否要搜索。模型提出新研究线索可等待下一次或独立研究，不能在已耗尽预算后再开启无限研究循环。

首个独立适配为 Brave Web Search。高级 base URL 支持该适配对应的协议或兼容网关；“可填写地址”不意味着任意搜索公司的 API 无需适配即可使用。其他协议通过新增 adapter 接入。

v0.1 首批证据使用搜索返回的来源和可获得摘录，清楚标明摘录来源及覆盖。完整网页/PDF 抓取需要以后单独的获取、大小限制、来源许可和隔离任务；不能把未阅读全文称为已阅读全文。

### 8.5 历史基线与资料可信度

基线资料保存现实历史，世界线事件保存本次实际结果。玩家救下本该死亡的人物后，本世界不能用史实死亡日期自动覆盖其存活状态。未影响的背景可参考基线继续推演。

来源类型标识用户指定、原始史料/官方研究项目、学术资料、百科机构、一般网页。顺序是检索偏好，不是绝对真理排序；用户指定来源也可能存在争议。支持多个相冲突 claim 同时保存。

史实日期适用范围、人物生卒、职位、技术、地名和交通作为重点研究类型。已有明确证据与世界叙述冲突时提示疑似时代错误，可查看资料、接受修正或保留玩家世界设定；不以一次搜索直接删除游戏事实。

### 8.6 明确计数与预算

| 限制 | 默认值 | 计数原则 |
|---|---|---|
| 模型请求/操作 | 最多 2 次 | 生成、提取、修复、模型研究、自动重试全部计入 |
| 独立搜索/操作 | 最多 1 次 | 不通过分页、多轮查询规避次数 |
| 采用搜索结果 | 最多 5 条 | 去重后、与问题和年代相关的结果 |
| 自动跨商 fallback | 关闭 | 显式配置后才可开启，仍需计数与留痕 |
| 摘要调用 | 独立任务、独立计数 | 达阈值生成；预算不足延后 |
| 费用金额 | 有单价时估计 | usage 未知或单价缺失显示未知，禁止填 0 冒充免费 |

达到调用上限后，保存失败或待处理状态，提供恢复动作。手动重新生成是新操作，界面和记录区分“同操作重试”与“新的付费请求”。

请求超时不证明服务商没有收费。自动重试先判断是否已有响应与剩余额度；已收到部分内容后不静默重发整回合。成本记录区分服务商实际 token usage、估计 token、用户单价计算金额和服务商实际账单。

快进每阶段按普通操作计数，界面记录累计阶段和调用量；默认到本阶段结束或选择点暂停，继续下一阶段由玩家触发。后台摘要和主动研究的调用不能藏在“本回合仅一次”的统计之外。

## 9. 平台秘密、文件与故障恢复

### 9.1 SecretStore 的具体方案

统一接口提供保存、核心读取、删除和查询是否已配置。首次用户输入自然经过 UI，保存成功后不再把明文 Key 回传前端；前端不把它写入 localStorage、浏览器持久状态或普通设置 JSON。

Windows 使用当前用户 DPAPI 加密，不启用机器级共享解密范围。密文保存在应用私有设置区域，数据库只保存 secret_ref。

Android 编写最小 Kotlin 原生插件，用 Android Keystore 生成 AES-GCM 密钥，加密 API token，并将带必要 IV/版本信息的密文保存到应用私有目录。Rust Provider 通过适配层获取解密值，只用于网络请求。API token 本身不是一个直接塞入 Keystore 的密码学密钥。

不采用硬编码保险库口令，不把 Stronghold 和系统 Keystore 当作同一机制。所选方案若在 M01 无法验证，记录复现和限制后修订决策，不静默退回明文。

设备迁移、系统密钥失效或应用数据清除后需要重新配置服务 Key。秘密不可恢复时不阻止阅读游戏存档。Android 自动备份行为需在技术验证中明确，避免恢复一份无法解密的 token 而一直显示“配置可用”。

### 9.2 外部资料与权限

网络资料进入应用时只作为数据。它不能更改系统规则、Provider 配置、秘密、磁盘文件或世界状态。模型不能获得 shell、任意文件访问或存档删除工具。

网页 Markdown/HTML 展示禁用脚本和危险链接协议；用户点击来源 URL 才打开外部页面。研究请求不附加模型供应商 Authorization，Provider 认证只发送给用户配置的对应端点。

用户可以指定自定义 API 或搜索网关地址；从网页得到的地址不能自动成为请求配置。日后添加完整抓取器时另行验证重定向、大小、超时、内网地址和提示注入边界。

来源内容只通过受限上下文区域提供给模型，状态必须由回合白名单变化校验并提交。注入防护既要约束提示，也要让核心权限与数据流实际无法执行高权限操作。

### 9.3 数据库、迁移与备份

应用数据目录中的每世界数据库启用 foreign_keys，短事务和明确的忙等待；M01 验证 WAL 与同步策略，正式提交以可恢复持久性为目标。数据库工作不运行在前端线程或阻塞网络执行循环。

首期保存格式版本为 1，新增迁移按顺序记录。迁移前生成一致备份，迁移使用事务，失败仍保留可用的旧库；未知较新版本拒绝自动降级写入，允许用户保留原文件再使用匹配版本。

一致备份通过 SQLite Online Backup 或经过验证的等价方法生成，不能仅复制仍在使用的主库文件而遗漏 WAL。备份完成后验证可读取，再替换目标文件或更新成功记录。

初期默认每 20 个正式回合建立一个恢复备份，保留最近 5 份；迁移前备份独立保留到迁移验收成功。用户手动导出不受自动备份轮换清理。保留数和间隔后续可在设置中调整。

### 9.4 单文件存档包

`.timejump` 为压缩包，至少包含：

```text
manifest.json       # 格式版本、应用版本、世界标识、导出时间
save.sqlite         # 一致世界数据库，不包含秘密
transcript.md       # 可读剧情，注明世界线范围
sources.json        # 已采用来源及结论状态
checksums.json      # 包内文件校验
```

其他可读状态或时间线导出可以增加，但 SQLite 与 manifest 的格式约定是导入依据。包内不包含 API Key、认证头、原始秘密存储、签名材料或默认完整诊断日志。

校验用于检测损坏，不能当作证明来源可信的数字签名。导入拒绝目录穿越、危险绝对路径、无法处理的版本与不完整数据库，在私有临时目录完成结构、校验、SQLite integrity_check 与引用一致性检查后再安装新存档。

导入默认创建一个新的本地世界 ID，更新世界级归属字段，保留同库内部实体/回合关系及原世界标识作为导入来源。不能默默覆盖现有世界；现有世界与导入世界在独立文件中隔离。

导入的模型配置只保留非秘密内容，提示绑定本机已配置服务或重新设置。导入失败不删除原包，不改变已有正式存档。

### 9.5 Android 文件 I/O

系统文档选择器返回 content:// URI，经平台 FileAccess 读取或写入，不直接交给 std::fs 或 rusqlite 当文件路径。

导入流程：选中单文件 → 复制到私有临时目录 → 校验 → 新建世界库 → 更新列表。导出流程：私有目录生成一致包 → 请求系统目标文件 → 写出 → 明确成功或失败。

取消选择器不算导入错误；写目标失败时保留内部导出结果供重试。v0.1 不依赖 Android 文件夹选择器或全盘存储权限，至少测试本地系统文档提供器。

### 9.6 中断与恢复矩阵

| 情况 | 正式世界状态 | 必须保留与恢复 |
|---|---|---|
| 开局模型失败 | 不建立半世界 | 开局配置、操作原因、重试入口 |
| 模型 429/超时/拒绝 | 停在旧 head | 玩家输入、调用计数、错误类别 |
| 流式输出中断 | 草稿未提交 | 已保存草稿和行动；重试可能重新计费 |
| JSON/状态验证失败 | 停在旧 head | 原输出、验证原因、剩余修复机会 |
| 验证成功但数据库失败 | 回滚全部正式写入 | 完整候选结果，允许重新提交前核验 head |
| 写入完成后 UI 丢失通知 | 正式回合已存在 | 按 operation 查询同一结果，不重新结算 |
| Android 锁屏/切后台 | 不承诺网络继续 | 若尚在运行可恢复 UI；被杀标记中断 |
| App 被强制结束 | 已提交数据完整 | 启动扫描未结束 operation，回到正式节点 |
| 快进暂停后终止 | 停在已提交决策点 | 目标、关注项和未做选择仍存在 |
| 迁移失败 | 旧格式可恢复 | 升级前备份、错误和应用兼容说明 |
| Key 无法解密 | 存档可读 | 配置显示需重设；不输出密文或秘密 |

### 11.3 Provider 故障与协议测试

覆盖普通文本、合法 JSON、围栏 JSON、错误版本、未知状态操作、空正文、截断、拒绝、SSE 多行、中文跨字节分片、结束标记、取消、超时、429、401、5xx、usage 缺失与非标准错误内容。

核验真正的流式响应而不是 HTTP 200；错误内容不泄漏 Key；两个生成路线都遵守两次请求上限；失败不导致自动无限调用。对使用者端点不预设其原生搜索和 schema 支持。

### 11.5 Android 短清单

1. 安装测试 APK，冷启动并设置 API。

3. 生成时切后台、锁屏或断网，再返回。

6. 有分支/快进后，验证切分支、暂停和恢复。

### 12.2 明确假设

用户自备模型服务与 Key，可以提供 Android 手机进行阶段体验。独立搜索可配置，但允许未配置时正常使用模型和存档。现实中任意历史背景的资料质量不一致，模型质量、端点功能与价格也会变化。

任意时代自由行动通过模型推演实现，不预置完整全世界百科。NPC 认知首期围绕玩家相关人物维护。正式状态可以有规则保证，历史真实性和文本推演需要证据与评测。

开发按验收门槛推进，重大路线失败时依据证据修订计划；未给固定工期。远期模块在进入实施前补充专门规格，不让当前开发者凭一个愿景条目自行实现完整系统。

### 12.3 待验证或待确定

Android 最低版本及真实设备、原生库 16 KB 运行、平台密钥与文件适配、rusqlite/reqwest 跨端构建、端点能力、真实模型叙事质量、实际中文召回与性能都需实测。

许可证在首次公开分发前确定。上述事项在 [DECISIONS.md](DECISIONS.md) 标注待验证，在任务台账安排对应验证，不作为文档交付的假完成条件。
